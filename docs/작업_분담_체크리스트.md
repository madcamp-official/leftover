## 0. 먼저 정할 것 — 캐릭터 동작 표현 방식

게임별 프레임 이미지는 아직 게임 로직에 연결되지 않았다. 다만 **돌던지기는 프레임
애니메이션 사용으로 확정**됐으며, 투척 순간에는 관절 리깅을 사용하지 않는다. 나머지 게임의
표현 방식은 별도로 결정한다. 연결하려면 공용 `CavemanSilhouette` 또는 신규 컴포넌트에
"n초 동안 프레임 배열 재생 후 기본 상태 복귀" 기능이 필요하다.

- [x] **돌던지기 결정**: 손 방향별 정면/후면 프레임 애니메이션을 사용
- [ ] 나머지 게임은 관절 리깅/프레임 애니메이션 사용 여부를 게임별로 결정
- [x] `CavemanSilhouette` 또는 신규 컴포넌트에 "n초 동안 프레임 배열 재생 후 기본 상태
      복귀" API를 만들어 재사용 — `FrameAnimatedCharacter.cs`로 구현됨

## 4. 백엔드(vision-server) 실행 환경 준비 (각자 자기 PC/노트북)

> 자세한 절차는 [`vision-server/README.md`](../vision-server/README.md),
> [`게임_구동방식_정리.md` 3장](게임_구동방식_정리.md#3-lan-연결-설정-방법) 참고. "백엔드"라고
> 부를 만한 서버를 새로 만드는 건 아니고, 각자 노트북에서 포즈 인식 프로세스를 띄우고
> 서로 LAN으로 연결하는 설정이다.

- [ ] 각자 노트북에 `vision-server/.venv` 만들고 `pip install -r requirements.txt`
- [ ] `models/face_landmarker.task` 다운로드 확인(없으면 입벌림/눈감김이 계속 기본값 —
      눈빛싸움/과일따기/돌바나나가 제대로 안 됨). `pose_landmarker_lite.task`는 이미 레포에 있음
- [ ] Unity를 실행할 PC 한 대 정하기(둘 중 하나, 또는 별도 PC)
- [ ] 같은 공유기/핫스팟(같은 LAN)에 두 노트북 + Unity PC가 붙어 있는지 확인
- [ ] Unity PC 방화벽에서 UDP 9100 인바운드 허용(Windows Defender 방화벽 고급 설정)
- [ ] 리허설: `python main.py --pc-ip <Unity PC IP> --player-id p1` /
      `--player-id p2`로 두 노트북에서 동시 실행 → Unity `Hub` 씬 Play → 카메라 프리뷰에
      랜드마크가 잘 잡히는지, Unity 콘솔에 UDP 바인딩 에러가 없는지 확인
- [ ] 실제 데모 장소(발표 환경) 조명/카메라 거리로 한 번 더 리허설 — 조명에 따라 인식률이
      크게 달라짐

## 5. 실측 튜닝 & QA (둘 다, 실제로 플레이해보면서)

각 미니게임 문서의 "조정 가능한 값" 표에 있는 임계값은 전부 추정치라 실측이 필요하다:

- [ ] 돌던지기 — `fireIntervalSeconds`, `dodgeTiltThreshold`
- [ ] 과일따기 — `tierHeightThresholds`, **카메라 프레이밍**(정점에서 머리가 프레임 밖으로
      안 나가는지 — [03_과일따기.md 13장](minigames/03_과일따기.md#13-미해결--todo) 참고)
- [ ] 코코넛깨기 — `hitDistance`, `releaseDistance`
- [ ] 돌 or 바나나 — `turnTimeoutSeconds`
- [ ] 눈빛싸움 — `earThreshold`, `loseAfterClosedSeconds`, `loseAfterTotalClosedSeconds`
      (사람마다 눈 크기 편차 큼 — 캘리브레이션 필요 여부 재확인)
- [ ] 5개 게임 각각의 문서 12번 "구현 완료 기준(Acceptance Checklist)"을 실제로 플레이하며
      하나씩 체크
- [ ] 최종적으로 `Hub` 씬에서 5판 풀 매치를 처음부터 끝까지 한 번 통과(중간 씬 전환/결과
      화면까지 포함해서)
