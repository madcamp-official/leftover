## 배경

기존 `leftover` 레포에는 `vision-server/`(Python, MediaPipe Pose Landmarker로 웹캠에서 상체
관절을 인식해 UDP로 이벤트를 보내는 서버)와 `pc-game/`(Unity, 3D 검투 게임 프로토타입)이
있다. **3D 검투 게임 컨셉은 전부 폐기한다.** `vision-server/`의 "웹캠 → MediaPipe → UDP로
Unity에 전송" 기본 골격(포트 구조, JSON 직렬화 패턴, 백그라운드 스레드+큐로 Unity 메인
스레드에 안전하게 전달하는 패턴)은 검증된 코드이니 재사용하되, 인식 대상과 전송 내용, 그리고
Unity 쪽 프로젝트는 완전히 새로 만든다: **Unity 2D**, 캐릭터는 원시인, 미니게임 6종을 순서대로
진행하는 1:1 파티 게임.

## 전체 컨셉

두 사람이 각자 자기 카메라(노트북 웹캠 등) 앞에 선다. 처음에는 웹캠 한 대 앞에 두 사람이
같이 서서 화면 좌/우로 구분하는 구조로 설계했지만, 실제로 만들어서 테스트해보니 두 사람이
붙어 있으면 사람 감지 단계에서 한쪽이 인식되지 않는 문제가 확인돼 **플레이어 1명당 카메라
1대(온라인 모드)** 로 바꿨다 — 각자의 카메라는 자기 자신만 인식하면 되므로 이 문제 자체가
사라진다. Unity는 두 PC 중 한쪽(또는 별도 PC)에서만 실행되고, 두 사람은 그 화면을 같이
보면서 플레이한다(화면이 두 개로 나뉘어 각자 다른 화면을 보는 구조는 아님 — 진짜 원격/분산
멀티플레이는 이번 범위 밖). 각자 원시인 캐릭터로 게임에 등장하며, 6개의 미니게임을 **고정된
순서로 한 판씩** 진행한다. 각 미니게임은 승/패가 명확히 갈리고, 6판이 끝나면 더 많이 이긴
사람이 최종 승자.

**캐릭터 아트**: 처음엔 도형/실루엣으로 구현했지만, 지금은 실제로 그린 원시인 일러스트
파츠(머리·몸통·상완·하완×2·대퇴·하퇴×2, 캐릭터 1/2 각각 고유 얼굴·머리색)를 관절 리깅해서
쓴다 — 어깨/팔꿈치 피벗이 포즈 추적값에 따라 회전한다. 원본은
`image/characters/character1`·`character2`의 `joints/front`·`joints/back`, Unity 임포트본은
`Assets/Resources/Characters`,
런타임 조립 로직은 `Assets/Prefabs/Caveman_P1.prefab`·`Caveman_P2.prefab` +
`CavemanSilhouette.cs`. 표정은 상황별 얼굴 스프라이트를 교체하거나 기존 얼굴 위에 오버레이한다.
대부분의 기본 자세는 관절 리깅을 사용할 수 있지만, **돌던지기의 투척 동작은 손 방향별 정면·
후면 프레임 애니메이션**(`image/characters/*/games/01_stone_throw/animation`)을 사용하는 것으로
확정했다. 돌에 맞으면 앞모습 전신을 `expressions/grimacing_fullbody.png`로 잠시 교체한다.

## 기술 아키텍처

```
[카메라 A, P1의 PC] → vision-server(Python, MediaPipe, --player-id p1)  ─┐
[카메라 B, P2의 PC] → vision-server(Python, MediaPipe, --player-id p2)  ─┤ UDP 9100
                                                                          │ (같은 LAN)
                                                                          v
                                                     pc-game(Unity 2D) - 한 PC에서만 실행,
                                                     두 사람이 이 화면을 같이 봄
```

각 vision-server 인스턴스는:
- Pose Landmarker: 상체+얼굴 위치 기반 관절(어깨/팔꿈치/손목/코/엉덩이/무릎/발목) — 자기
  카메라에 잡힌 사람을 실행 인자로 받은 고정 id(`p1`/`p2`)로 라벨링(카메라 1대=1명이라 좌/우
  구분 자체가 필요 없음)
- Face Landmarker: 눈 랜드마크(EAR 계산용) — Pose와 별도 모델이지만 같은 루프에서 같은
  프레임에 대해 함께 추론
- UDP로 Unity PC에 프레임마다 연속 전송(기존처럼 "인식된 동작 이벤트" 이산 전송이 아니라
  관절 좌표/눈 상태를 그대로, 매 프레임 스트리밍 — 미니게임들이 필요로 하는 값이 제각각이라
  분류를 미리 서버에서 끝내기보다 원시값을 보내고 Unity 쪽에서 게임별로 해석하는 게 더 유연함)

두 인스턴스가 각자 자기 담당 플레이어 한 명만 담긴 프레임을 같은 포트로 보내고, Unity의
`PoseInputHub`는 프레임에 들어온 id만 갱신하는 구조라 두 스트림이 자연스럽게 합쳐진다 —
카메라 1대에 두 명을 같이 인식하던 초기 방식(구모드)은 `vision-server/README.md`에 남아있다.

### 공용 모듈 (모든 미니게임이 재사용)

- **P1/P2 랜드마크 스트림 수신기**: UDP 수신 → 최신 프레임의 P1/P2 각각의 관절 좌표를 보관하는
  단일 컴포넌트. 모든 미니게임 씬이 이걸 통해서만 입력을 읽는다(미니게임 로직이 UDP/JSON을
  직접 몰라도 되게).
- **손 들기 인식**: 손목 y좌표가 어깨 y좌표보다 일정 값 이상 위에 있으면 "들었다"로 판정, 왼손/
  오른손 각각 독립 판정.
- **머리 기울기 인식**: 코-어깨중심 각도 또는 귀 좌표 기울기로 좌/우 기울임 판정.
- **입 벌림 인식**: 입술 랜드마크 상하 간격이 기준치 이상 벌어지면 "벌림"으로 판정.
- **점프 높이 계산**: 각 사람마다 게임 시작 시 1~2초간 "가만히 서 있는" 자세를 기준선으로
  캘리브레이션하고, 이후 몸통 기준점이 그 기준선에서 얼마나 올라갔는지로 높이 측정 — 실제
  키/캠 거리 차이에 영향 안 받게(정확한 기준점 선택과 판정 시점은
  [03_과일따기.md](minigames/03_과일따기.md) 참고 — 최초 기획은 발목 기준이었으나 구현
  과정에서 엉덩이 중점 기준으로 바뀌었다).
- **눈 감김 인식(EAR)**: Face Landmarker의 눈 랜드마크로 Eye Aspect Ratio 계산, 임계값 이하가
  일정 시간(기본 0.4초) 이상 지속되면 "눈 감음"으로 판정 — 순간적인 자연 깜빡임은 무시.
- **손-머리 거리 인식**: 코코넛 깨기용, 양손 중심과 머리 중심 사이 거리를 매 프레임 계산.

## 구현 우선순위 제안

1. 공용 모듈부터: P1/P2 좌우 분리 + UDP 스트리밍 파이프라인(vision-server 쪽 최소 수정 +
   Unity 수신기) → 이게 되어야 나머지 전부가 움직임.
2. 가장 단순한 것부터 프로토타입: **눈빛 싸움**(조작 없음, 판정 로직만) → **코코넛 깨기**(반복
   카운트만) → 나머지 4개.
3. 미니게임 간 공통 UI(라운드 전환 화면, 스코어보드, 승자 표시)는 마지막에 한 번에 통일.

## 아직 남은 세부 조정값들

각 미니게임의 정확한 임계값(발사 주기, 판정 오차, 게이지 최대치 등)은 전부 실제 플레이
테스트를 거쳐야 확정되는 숫자다 — 최신 기본값과 실측 필요 여부는 각
[minigames/](minigames/) 문서의 "조정 가능한 값"/"미해결" 섹션을 참고할 것(이 문서에는 더
이상 개별 수치를 중복 기재하지 않는다).
