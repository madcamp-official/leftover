# 8. 깃털날기 (Feather Flight)

> 기획 단계 — 아직 씬/스크립트 없음. 예정 코드: `Assets/Scripts/Minigames/FeatherFlight/FeatherFlightGame.cs`,
> `FeatherFlightHud.cs`. 예정 씬: `Assets/Scenes/FeatherFlight.unity`.

## 0. 한 줄 요약

절벽에서 뛰어내린 뒤 양팔을 계속 퍼덕여야만 추락을 늦출 수 있다 — 날갯짓이 느려지는 순간
바닥으로 떨어져 패배하고, 제한시간이 끝났을 때 더 높이 떠 있는 쪽이 승리한다.

## 1. 플레이어가 하는 일

| 동작 | 결과 |
|---|---|
| 양팔을 벌려 위로 들어올림(날갯짓 1회) | 캐릭터 높이가 `flapBoost`만큼 즉시 올라감 |
| 아무것도 안 함 | 높이가 `fallSpeed`로 계속 일정하게 줄어듦(중력) |
| 날갯짓을 충분히 자주 반복 | 상승분이 하강분을 상쇄해 공중에 계속 떠 있음 |
| 날갯짓이 느려져 높이가 0에 닿음 | 그 즉시 패배(제한시간과 무관하게 즉사) |
| 제한시간이 끝날 때까지 버팀 | 그 순간 더 높이 떠 있는 쪽이 승리 |

캐릭터는 뛰어내린 뒤 좌우로 전진하지 않는다 — 화면 안 고정된 자리에서 위아래로만 움직인다.

## 2. 입력 신호 (PoseInputHub API)

| 신호 | 메서드/필드 | 이 게임에서의 의미 |
|---|---|---|
| 양손 들기 | `state.IsHandRaised(rightHand: true)`, `state.IsHandRaised(rightHand: false)` | 두 값이 **동시에** true인 프레임을 "양팔이 올라간 상태"로 본다 |
| 트래킹 여부 | `state.IsTracked` | false인 프레임은 양손 다 안 든 것으로 취급(날갯짓 판정 없음, 아래 로 취급) |

이 게임은 새 신호가 필요 없다 — 기존 `IsHandRaised`를 양손에 각각 호출해서 조합하는 것으로
충분하다. 다만 "1회 날갯짓"은 순간값이 아니라 **양팔이 오른 순간(rising edge)**만 세는
엣지 검출이 필요하다 — 3장 참고.

## 3. 규칙 / 상태 흐름

플레이어별로 독립된 상태(`height`, `bothHandsRaisedPrev`)를 매 프레임 갱신한다. 두 캐릭터는
서로 영향을 주지 않는다(각자 자기 절벽에서 독립적으로 진행, 같은 화면에 동시에 보임).

```
[매치 시작] --즉시--> height = maxHeight (절벽 꼭대기에서 뛰어내린 직후 높이)
                       bothHandsRaisedPrev = false

[비행 중] --매 프레임--
    bothHandsRaisedNow = IsTracked && IsHandRaised(left) && IsHandRaised(right)

    height -= fallSpeed * Time.deltaTime   (지속적인 하강)

    if bothHandsRaisedNow && !bothHandsRaisedPrev:
        # 날갯짓 1회 = 양손이 "안 든 상태"에서 "든 상태"로 바뀌는 그 프레임에만 카운트.
        # 양손을 든 채로 계속 버텨도 추가로는 카운트되지 않는다 - 다시 내렸다 들어야 함.
        height += flapBoost
        height = min(height, maxHeight)   # 최고 높이를 넘어서지는 않음

    bothHandsRaisedPrev = bothHandsRaisedNow
    height = max(height, 0)

[비행 중] --height <= 0--> 그 즉시 패배(상대 승리), 매치 종료
[비행 중] --elapsed >= matchSeconds(아직 아무도 안 떨어짐)--> [판정]

[판정] --p1Height > p2Height--> P1 승리
[판정] --p2Height > p1Height--> P2 승리
[판정] --p1Height == p2Height--> 무승부
```

**타임라인 예시** (`fallSpeed = 1.2`/초, `flapBoost = 0.35`, `maxHeight = 4.0`):

1. `t=0.0s` 뛰어내린 직후, `height = 4.0`(최고 높이).
2. 날갯짓을 전혀 안 하면 `t=1.0s`에 `height = 4.0 - 1.2 = 2.8`, `t=3.33s`쯤 `height = 0`에
   닿아 패배.
3. `t=0.5s`에 양팔을 들어올리면(직전 프레임까지 안 들었던 상태에서) 그 프레임에만
   `height += 0.35` — 그 사이 계속 든 채로 있어도 추가 상승은 없다. 다시 내렸다가
   `t=0.8s`에 또 들어올리면 두 번째 날갯짓으로 다시 `+0.35`.
4. 평균적으로 `fallSpeed / flapBoost ≈ 3.4`초에 한 번보다 더 자주 날갯짓해야 높이가
   유지된다(정확한 필요 빈도는 `fallSpeed`를 `flapBoost`로 나눈 것 = 초당 필요 날갯짓 횟수).

## 4. 승리 / 패배 조건

- 한쪽의 높이가 0에 닿는 즉시 그 자리에서 패배, 상대가 승리(제한시간 전이라도 즉시 종료).
- 정확히 같은 프레임에 둘 다 0에 닿으면 무승부.
- `matchSeconds`가 지날 때까지 아무도 떨어지지 않으면, 그 순간 높이가 더 높은 쪽이 승리하고
  같으면 무승부.

## 5. 화면 구도

- 카메라: 좌우 절반으로 나뉜 고정 시점(다른 게임의 오버더숄더 분할과 달리, 여기서는 두
  플레이어가 그냥 화면 왼쪽/오른쪽에 각자 보임).
- **공통 배경**: 공중 옆면 시점의 하늘·구름·먼 정글과 우스꽝스러운 새가 그려진 배경 한 장을
  화면 전체에 사용한다.
- **왼쪽 절반(P1)**: 화면 왼쪽 끝에 투명 P1 절벽을 배치한다. P1은 절벽 위에서 화면 중앙
  방향으로 점프해 날아든 뒤, 중앙에 가까운 고정 x좌표(`p1HoverAnchor`)에서 높이(`height`)에
  따라 세로로만 움직인다.
- **오른쪽 절반(P2)**: 왼쪽 절반과 좌우 대칭인 구도 — 절벽이 화면 오른쪽 끝에서 시작하고,
  P2는 화면 중앙 방향(왼쪽)으로 점프해 날아든 뒤 `p2HoverAnchor`에서 세로로만 움직인다.
  `cliff_p2.png`는 `cliff_p1.png`를 픽셀 단위로 정확히 좌우 반전한 파일이다.
- 캐릭터: 캐릭터별 전용 프레임 애니메이션을 사용한다. P1은 오른쪽을 향하고 P2는 왼쪽을
  향한 절벽 점프 4컷과 양손에 깃털을 하나씩 든 날갯짓 3컷(팔 위·중간·아래)을 사용한다.
- `height`는 화면 세로 위치로 그대로 매핑한다: 화면상 y좌표 = `hoverAnchorBaseY +
  height`(월드 유닛 그대로 1:1 대응). `maxHeight`가 곧 화면에서 캐릭터가 도달할 수 있는
  가장 높은 위치가 되도록 카메라 orthographicSize와 맞춰 잡는다.

## 7. 연출 / 피드백

- **날갯짓 반응**: 날갯짓이 카운트되는 프레임에 캐릭터가 살짝 위로 튀어 오르는 모션(또는
  깃털 파티클 살짝 흩날림)으로 눈에 보이는 피드백을 준다 — 안 그러면 날갯짓이 실제로
  카운트됐는지 체감이 안 될 수 있다.
- **추락 임박 경고**: `height`가 `maxHeight`의 일정 비율(예: 20%) 이하로 내려가면 캐릭터
  주변에 위험 이펙트(빨간 테두리 등)를 표시해 위기감을 준다(TODO: 구체 임계값 미정).
- **패배 연출**: `height`가 0에 닿는 순간 캐릭터가 화면 아래로 떨어지는 짧은 낙하 모션
  재생 후 결과 문구 표시.
- **사운드**: 미구현. TODO — 날갯짓 효과음, 추락 효과음.

## 8. 조정 가능한 값

| 필드명 | 기본값 | 단위 | 의미 |
|---|---|---|---|
| `matchSeconds` | 20 | 초 | 라운드 제한시간 |
| `maxHeight` | 4.0 | 월드 유닛 | 시작 높이이자 최대 높이(절벽 꼭대기) |
| `fallSpeed` | 1.2 | 유닛/초 | 매 프레임 지속적으로 줄어드는 하강 속도 |
| `flapBoost` | 0.35 | 유닛 | 날갯짓 1회(양손 rising edge)당 즉시 더해지는 높이 |
| `raiseRatio`(양손 판정) | 0.15 | 비율 | `IsHandRaised`에 전달하는 임계값(공용 기본값 그대로 사용) |
| `resultDisplaySeconds` | 2.0 | 초 | 승패 문구 표시 후 다음 라운드로 넘어가기 전 대기 시간 |

**날갯짓에 필요한 최소 빈도** = `fallSpeed / flapBoost`(위 기본값 기준 약 3.43회/초) — 값을
조정할 때는 이 계산으로 "실제로 사람이 양팔을 그 속도로 반복할 수 있는지"를 먼저 가늠해볼 것.

## 10. 예외 / 엣지 케이스

- **한쪽만 트래킹 끊김(`IsTracked == false`)**: 그 프레임은 양손 다 안 든 것으로 취급되어
  날갯짓이 카운트되지 않는다(하강은 계속 진행) — 카메라 밖으로 나가면 그만큼 손해를 본다.
- **양손을 든 채로 계속 버팀**: 처음 든 순간에만 1회 카운트되고, 내렸다가 다시 들지 않는
  한 추가 상승이 없다 — 팔을 들어올린 채 고정해서 무한정 버티는 전략은 통하지 않는다(3장
  참고).
- **한쪽 손만 듦**: 날갯짓으로 카운트되지 않는다(양손이 동시에 필요) — 한쪽 팔만 흔드는
  것은 아무 효과가 없다.
- **정확히 같은 프레임에 둘 다 height == 0**: 무승부 처리.
- **제한시간 종료 시점에 정확히 같은 높이**: 무승부 처리.
- **`height`가 이미 0인데 그 이후에도 계속 날갯짓**: 이미 그 프레임에 패배가 확정되어
  매치가 끝났으므로 이후 입력은 의미가 없다(별도 처리 불필요).
