# 5. 돌 or 바나나 (Stone or Banana)

> 코드: `Assets/Scripts/Minigames/StoneOrBanana/StoneOrBananaGame.cs`, `StoneOrBananaHud.cs`.
> 씬: `Assets/Scenes/StoneOrBanana.unity`.

## 0. 한 줄 요약

던지는 사람은 오른손/왼손으로 돌과 바나나 중 뭘 던질지 숨기고, 받는 사람은 입을 벌여
먹을지 다물어 피할지 매 턴 도박을 한다 — 돌을 잘못 먹으면 이빨이, 바나나를 피하면
부메랑처럼 되돌아와 이번엔 던진 사람이 같은 도박을 해야 한다.

## 1. 플레이어가 하는 일

| 동작 | 결과 |
|---|---|
| (던지는 차례) 오른손 들기 | 돌을 던짐 |
| (던지는 차례) 왼손 들기 | 바나나를 던짐 |
| (던지는 차례) 양손 다 들기 | 오른손 우선(돌 던지기로 처리) |
| (받는 차례) 입 벌리기 | 날아온 게 뭐든 먹는다 — 바나나면 포만감 획득, 돌이면 이빨 손실 |
| (받는 차례) 입 다물기(또는 `turnTimeoutSeconds` 동안 계속 벌리지 않음) | 날아온 게 뭐든 피한다 — 돌이면 아무 일도 없음, 바나나면 던진 사람에게 부메랑처럼 되돌아감 |
| (부메랑으로 돌아온 바나나를 받는 차례가 된 최초 던진 사람) 입 벌리기 | 포만감 획득(자기가 던진 바나나를 자기가 다시 받아먹는 것) |
| (부메랑 바나나를 못 받음) | 페널티 없이 그냥 놓침, 턴 종료 |

## 2. 입력 신호 (PoseInputHub API)

| 신호 | 메서드/필드 | 이 게임에서의 의미 |
|---|---|---|
| 오른손 들림 | `state.IsHandRaised(rightHand: true)` | (던지는 사람) 참이면 돌 던지기 |
| 왼손 들림 | `state.IsHandRaised(rightHand: false)` | (던지는 사람) 오른손이 안 들렸고 이게 참이면 바나나 던지기 |
| 입 벌림 | `state.IsMouthOpen()` | (받는 사람) 참이면 그 즉시 "먹음"으로 판정 |
| 트래킹 여부 | `state.IsTracked` | 던지는 사람이 false면 던지기 판정을 아예 하지 않고 대기, 받는 사람이 false면 "먹음"이 false로 처리(=계속 피하는 중으로 취급, 타임아웃되면 피함으로 확정) |

`PlayerPoseState`는 `PoseInputHub.Instance.Get(PlayerId.P1 / P2)`로 얻는다. 이 게임은 돌던지기와
같은 손 문법(오른손=공격 A, 왼손=공격 B)과 입 벌림만 쓰고, 머리 기울기 등 다른 신호는 쓰지 않는다.

## 3. 규칙 / 상태 흐름

이 게임은 P1/P2가 자원을 공유하는 턴제 게임이다(돌던지기·과일따기와 달리 두 사람이
독립적으로 진행하지 않는다) — 한 번에 한쪽만 "던지는 사람", 다른 쪽은 "받는 사람"이고,
턴마다 두 역할이 번갈아 바뀐다.

```
[WaitingThrow(던지는 사람=T)] --T가 오른손/왼손을 들면--> 그 순간 종류(돌/바나나) 확정, 투사체 발사 연출 시작 --> [WaitingCatch(받는 사람=상대)]

[WaitingCatch(받는 사람=C)] --C가 입을 벌림--> "먹음"
[WaitingCatch(받는 사람=C)] --turnTimeoutSeconds(8초) 동안 안 벌림--> "피함"

먹음/피함 결과 처리 (아래 "판정 결과 표" 참고):
  - 첫 캐치가 [돌]이면 -> 무조건 EndTurnAndAdvance (역할 교대)
  - 첫 캐치가 [바나나]이고 먹음이면 -> 받은 사람 포만감 +1, EndTurnAndAdvance
  - 첫 캐치가 [바나나]이고 피함이면 -> [BoomerangBackToThrower(받는 사람=원래 던진 사람 T)]로 전환, 바나나가 T에게 되날아가는 연출 시작

[BoomerangBackToThrower(받는 사람=T)] --T가 입을 벌림--> T의 포만감 +1, EndTurnAndAdvance
[BoomerangBackToThrower(받는 사람=T)] --타임아웃--> 페널티 없이 EndTurnAndAdvance

EndTurnAndAdvance: 승패 조건(4번 섹션)을 먼저 확인하고, 아무도 안 끝났으면 던지는 사람을
반대쪽으로 바꾸고 [WaitingThrow]로 복귀.
```

**판정 결과 표** (한 번의 캐치 시도에서 무슨 일이 일어나는지):

| 던진 것 | 받는 사람 반응 | 결과 |
|---|---|---|
| 돌 | 먹음(입 벌림) | 받은 사람 이빨 -1 (순수 페널티) |
| 돌 | 피함(입 다묾/타임아웃) | 아무 일도 없음, 그냥 턴 종료 |
| 바나나 | 먹음(입 벌림) | 받은 사람 포만감 +1, 턴 종료 |
| 바나나 | 피함(입 다묾/타임아웃) | 바나나가 던진 사람에게 부메랑처럼 되돌아감 — 이어서 던진 사람이 같은 판정을 한 번 더 받음(아래 행) |
| (부메랑) 바나나 | 던진 사람이 먹음 | 던진 사람 포만감 +1, 턴 종료 |
| (부메랑) 바나나 | 던진 사람이 피함/타임아웃 | 페널티 없음, 그냥 턴 종료 |

**판정은 투사체가 화면에 도착하기 전부터 열려 있다** — `WaitingCatch`/`BoomerangBackToThrower`
상태는 `FlyItem` 연출 코루틴 시작과 같은 프레임에 시작되므로, 받는 사람이 투사체가 실제로
자기 캐릭터에 도달하기 전에 입을 벌려도 그 즉시 "먹음"으로 인정된다(연출과 판정이 분리돼
있다 — 돌던지기와 같은 설계).

## 4. 승리 / 패배 조건

`EndTurnAndAdvance`가 매 턴 종료 시 다음을 순서대로 확인한다:

1. 자신의 이빨(`teeth`)이 0 이하가 되면 그 즉시 패배(즉사 조건 — 정상적으로 포만감을 채워
   이기는 것보다 우선 확인됨).
2. 자신의 포만감(`fullness`)이 `maxFullness`(기본 5) 이상이면 승리.
3. 둘 다 해당 없으면 게임 계속.

이빨/포만감은 정수가 아니라 float로 다루지만 매 이벤트마다 정확히 1.0씩만 증감하므로
사실상 정수처럼 움직인다. **무승부 규칙은 없다** — 한 번에 한 사건(먹음/피함)만 처리되고
그 즉시 승패를 확인하므로 두 사람이 동시에 조건을 만족하는 경우가 구조적으로 발생하지 않는다.

## 5. 화면 구도

- 카메라: `Orthographic Size = 3`.
- 배경: `image/games/stone_or_banana/background/background.png` 한 장, 카메라 뷰를 꽉 채움.
-화면을 좌/우로 절반씩 나눈다. **왼쪽 절반 = P1이 상대(P2)를 마주보는 시점, 오른쪽 절반 =
P2가 상대(P1)를 마주보는 시점**이다(둘 다 하나의 공유 화면에 동시에 보임 — 실제로 화면이
물리적으로 두 대인 게 아니라, 한 화면 안에서 왼쪽 구역/오른쪽 구역으로 나뉜다는 뜻).

각 절반 안의 배치:

| 위치 | 왼쪽 절반(P1 시점) | 오른쪽 절반(P2 시점) |
|---|---|---|
| 화면 중단 살짝 위 | **P2의 앞모습**, 와이드샷(전신이 보이는 먼 화각) | **P1의 앞모습**, 와이드샷 |
| 화면 하단 우측 | **P1의 뒷모습**, 바스트샷(상체 클로즈업) | **P2의 뒷모습**, 바스트샷 |

즉 왼쪽 절반은 "내가(P1) 상대(P2)를 정면으로 겨누고 있고, 내 뒷모습이 화면 앞쪽 아래
구석에 걸쳐 보이는" 오버더숄더 구도다. 오른쪽 절반은 그 반대(P2 시점)로 대칭.

**배경의 깊이 레이어**: 각 절반의 배경 아트는 원근감을 위해 세 개 층으로 구성한다고 가정
하고 그린다 — **하단(전경, 발밑 지면/바닥)**, **중단(중경, 실제 대결이 벌어지는 공간 —
와이드샷 인물이 서는 자리)**, **상단(원경, 하늘이나 먼 배경)**.

**뒷모습/앞모습 에셋 재구성 필요**

- `CoverBush`: 각 캐릭터의 자식 오브젝트로, 로컬 좌표 `(0, 0.35, 0)`(캐릭터 하반신 높이)에
  배치된 정적 수풀 스프라이트. 판정에는 관여하지 않는 순수 장식(정글 속에 몸을 반쯤
  가리고 있는 느낌을 주는 용도로 추정 — 코드에서 별도로 조작하지 않음).
- 투사체(돌/바나나)는 던진 사람 위치(`+ Vector3.up * 0.6`)에서 생성돼 받는 사람 위치까지
  `throwTravelSeconds`(0.5초) 동안 직선으로 날아간 뒤 사라진다. 부메랑 구간은 반대 방향으로
  같은 방식의 비행이 한 번 더 재생된다.

## 7. 연출 / 피드백

- **투사체 비행**: 돌/바나나가 직선으로 날아가는 연출(회전 없음, 돌던지기의 회전 연출과
  다름). 부메랑 구간은 방향만 반대인 같은 연출이 한 번 더 재생된다.
- **던지기/받기 안내 배너**: 지금이 던질 차례인지 받을 차례인지 화면 중앙 배너로 즉시 전환.
- **표정/이빨 변화**: 미구현 — 돌을 먹었을 때(이빨이 깨질 때), 바나나를 먹었을 때 캐릭터
  표정이 바뀌지 않는다. 관련 아트(`stone_hit_one_tooth_broken`, `stone_hit_two_teeth_broken`,
  `banana_chewing_puffed_cheeks`, `grimacing`)가 이미 캐릭터 파츠 폴더에 있지만 이 게임에서
  `CavemanSilhouette.SetFace`/`ResetFace`를 호출하는 코드가 없다(9번 참고).
- **사운드**: 미구현. TODO.

## 8. 조정 가능한 값

| 필드명 | 기본값 | 단위 | 의미 |
|---|---|---|---|
| `maxFullness` | 5 | 점 | 포만감이 이 값 이상이면 그 플레이어 승리 |

| `bananaWidth` | 0.45 | 월드 유닛 | 바나나 스프라이트 표시 폭 |

## 10. 예외 / 엣지 케이스

- **던지는 사람이 트래킹 안 됨(`IsTracked == false`)**: `TickWaitingThrow`가 조기 반환되어
  손을 들어도 아무 반응이 없다 — 트래킹이 복구될 때까지 `WaitingThrow` 상태에서 무한 대기
  (타임아웃 없음, 돌던지기와 다른 부분).
- **받는 사람이 트래킹 안 됨(`IsTracked == false`)**: `IsMouthOpen()` 체크 전에 `IsTracked`가
  false면 "먹음"이 항상 false로 계산되므로, 트래킹이 안 되는 동안은 계속 "피하는 중"으로
  취급되다가 `turnTimeoutSeconds`가 지나면 자동으로 "피함"이 확정된다(돌이면 무사, 바나나면
  부메랑으로 되돌아감).
- **타임아웃 정확히 그 프레임에 입을 벌림**: `ate` 판정이 `_turnTimer >= turnTimeoutSeconds`
  체크보다 먼저 이루어지므로, 정확히 같은 프레임이라도 입을 벌렸다면 "먹음"이 우선한다.
- **부메랑 중에도 받는 사람(=원래 던진 사람)이 트래킹 안 됨**: 위와 동일하게 타임아웃까지
  "피함" 대기 상태 유지, 최종적으로 페널티 없이 턴 종료.
- **이빨이 정확히 0이 되는 것과 포만감이 가득 차는 것이 이론상 같은 이벤트에서 동시 발생**:
  코드상 한 번의 캐치는 이빨 변화 또는 포만감 변화 중 하나만 일으키므로(돌=이빨만, 바나나=
  포만감만) 두 조건이 같은 턴에 동시에 만족되는 경우는 없다. `EndTurnAndAdvance`는 이빨 소진을
  포만감 완료보다 먼저 확인하므로, 설령 규칙이 바뀌어 동시 발생이 가능해지더라도 이빨 소진이
  우선 처리된다.
- **연속으로 같은 사람이 계속 던지는 차례를 받는 일은 없음**: `EndTurnAndAdvance`가 매번
  `_currentThrower`를 반대쪽으로 바꾸므로, 부메랑 판정까지 끝난 뒤에는 항상 던지는 역할이
  넘어간다 — 단, 부메랑 자체(같은 턴 안에서 받는 사람이 바뀌는 것)는 역할 교대가 아니다.
