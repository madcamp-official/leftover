# 3. 점프해서 과일따기 (Fruit Jump)

> 코드: `Assets/Scripts/Minigames/FruitJump/FruitJumpGame.cs`, `FruitJumpHud.cs`,
> `Assets/Scripts/Common/JumpHeightCalibrator.cs`.
> 씬: `Assets/Scenes/FruitJump.unity`.

## 0. 한 줄 요약

각자 자기 나무에서 높이 뛸수록 더 높은(더 비싼) 과일을 딴다 — 상대와 자원 경쟁은 없고,
순전히 자기 점프 실력만으로 점수를 쌓는 경주.

> **변경 이력**: 원래는 정점에서 입이 벌어져 있어야 채점되는 타이밍 조건이 있었으나,
> 카메라에서 멀어질수록 입 벌림(`IsMouthOpen`) 인식이 불안정해서 이 조건을 뺐다. 지금은
> 점프 높이(정점)만으로 단이 정해지면 곧바로 채점된다. 아래 표/흐름도는 이 변경을 반영해
> 수정했다.

## 1. 플레이어가 하는 일

| 동작 | 결과 |
|---|---|
| 낮게 점프해서 착지 | 낮은 단(사과) 획득 |
| 중간 높이로 점프해서 착지 | 중간 단(포도) 획득 |
| 높이 점프해서 착지 | 높은 단(파인애플) 획득 |
| 점프 내내 최고 단까지 도달 | 최고 단(파인애플)만 획득한다 — 도중에 낮은 단을 지나쳤어도 별도로 채점되지 않는다(한 점프 = 그 점프의 최종 정점 단 하나) |
| 점프 후 완전히 착지 | 방금 딴 과일은 다음 점프를 시작(이륙)하는 순간 다시 나타남 |

## 2. 입력 신호 (PoseInputHub API)

| 신호 | 메서드/필드 | 이 게임에서의 의미 |
|---|---|---|
| 점프 높이 | `JumpHeightCalibrator.GetJumpHeight()` | 캘리브레이션된 기준선 대비 상승 비율(몸통 길이 대비). 0 이상, 클수록 높이 뜬 것 |
| 트래킹 여부 | `state.IsTracked` | 캘리브레이터 내부에서 기준선 추적에 쓰인다. 트래킹이 끊기면 `GetJumpHeight()`가 0을 반환 |

입 벌림(`IsMouthOpen`)은 더 이상 이 게임의 채점에 쓰이지 않는다 — 거리가 멀어질수록
얼굴 인식이 불안정해 판정 신뢰도가 떨어졌기 때문(13번 TODO였던 항목을 조건 자체를 빼서 해소).

`PlayerPoseState`는 `PoseInputHub.Instance.Get(PlayerId.P1 / P2)`로 얻는다. `JumpHeightCalibrator`는
씬에 P1/P2용으로 하나씩 배치되어 있고, 내부적으로 **엉덩이 중점(`Joints.HipMid`)** y좌표를
스스로 추적하며 `PoseInputHub`를 읽는다 — 이 게임 코드는 `GetJumpHeight()`만 호출하면 된다.

발목이 아니라 엉덩이 중점을 기준점으로 쓰는 이유: 점프 정점에서는 발이 카메라 프레임 하단에
가까워 잘리거나 포즈 추정이 흔들리기 쉽지만, 몸통 중심에 가까운 엉덩이는 상대적으로 프레임
안쪽에 남아 추정이 더 안정적이다. 다만 이것도 만능은 아니다 — 아래 "10. 예외 / 엣지 케이스"의
카메라 프레이밍 항목 참고.

## 3. 규칙 / 상태 흐름

P1과 P2는 완전히 독립된 나무를 가지며 서로 영향을 주지 않는다(같은 화면에서 동시에 진행).
각 플레이어는 게임 시작 시 한 번 캘리브레이션을 거친다.

핵심 원칙: **판정은 실시간(프레임 단위)이 아니라 착지한 순간 한 번만 한다.** 점프 중에는
그 점프의 "정점 높이"(가장 높이 뜬 순간의 높이)만 계속 갱신해서 들고 있다가, 착지하는
순간 그 값으로 그 점프 전체의 결과를 딱 한 번 확정한다. 그래서 점프 내내 최고 단까지
올라갔다면 최고 단 과일 하나만 채점되고, 낮은 단들은 도중에 지나쳤더라도 별도로 채점되지
않는다.

```
[땅] --점프 높이가 tierHeightThresholds[0]*0.5 이상으로 상승(이륙)-->
     이전 점프에서 먹은 과일을 다시 보이게 함, PeakHeight=0으로 초기화
     --> [공중]

[공중] --매 프레임, height > PeakHeight이면--> PeakHeight = height로 갱신
     (하강이 시작되면 height가 더 이상 PeakHeight를 못 넘으므로 이 갱신은 자연히 멈춘다 -
     즉 마지막으로 갱신된 값이 "진짜 정점 높이"가 된다)

[공중] --점프 높이가 tierHeightThresholds[0]*0.5 미만으로 하강(착지)--> [땅]
     착지하는 그 프레임에 한 번만: PeakHeight로 도달한 가장 높은 단을 계산해 그 단 하나만
     곧바로 채점(과일 사라짐). 어떤 단에도 못 미쳤으면(PeakHeight가 가장 낮은 임계값
     미만) 이번 점프는 무득점
```

**단(tier) 판정 방법** — 착지 시점에, 이번 점프의 `PeakHeight` 하나로 "도달한 가장 높은 단"을 고른다:

```
tier = -1
for i = 2 downto 0 (파인애플 -> 포도 -> 사과 순, 즉 높은 단부터):
    if PeakHeight >= tierHeightThresholds[i]:
        tier = i
        break  # 가장 높은 단 하나만 고르고 더 낮은 단은 보지 않는다
if tier >= 0:
    score += tierScores[tier]
```

예를 들어 `tierHeightThresholds = {0.2, 0.4, 0.75}`일 때 어떤 점프의 최종 `PeakHeight =
0.5`이면 `tier = 1`(포도)이다 — 점프 도중 사과 임계값(0.2)도 분명히 넘었지만, 판정은
정점 하나만 보므로 사과는 애초에 후보에 오르지 않는다.

**매 프레임 하는 일** (플레이어별로 독립):

1. `GetJumpHeight()`로 현재 점프 높이를 읽고, 그 값만큼 캐릭터를 화면에서 위로 띄워 보여준다
   (`jumpBounceHeight`로 스케일).
2. `airborne = height >= tierHeightThresholds[0] * 0.5` 계산.
3. 방금 공중 상태로 바뀌었으면(이전 프레임엔 땅, 이번 프레임은 공중 = 이륙) 과일을 전부
   다시 보이게 하고(`RespawnFruits`) `PeakHeight`를 초기화한다.
4. 공중이면: `height`가 지금까지의 `PeakHeight`보다 크면 `PeakHeight`를 갱신한다.
5. 방금 땅 상태로 바뀌었으면(이전 프레임엔 공중, 이번 프레임은 땅 = 착지): 위 "단 판정
   방법"으로 이번 점프의 `tier`를 계산하고, `tier >= 0`이면 점수 획득(`+tierScores[tier]`),
   HUD/이벤트 텍스트 갱신, 해당 단 과일 스프라이트가 줄어들며 사라짐(`fruitEatSeconds`
   동안). 아무 단에도 못 미쳤으면 이번 점프는 그냥 무득점으로 끝난다(재시도 없음 — 다음
   점프를 새로 뛰어야 한다).

## 7. 연출 / 피드백

- **공중에 떠있는 동안**: 캐릭터는 화면에서 움직이지 않는다 — 점프 높이는 판정에만 쓰이고
  실시간으로 캐릭터 위치/자세에 반영되지 않는다(카메라 노이즈로 계속 떨리는 걸 보여주지
  않기 위함).
- **점수 확정 연출(착지 순간)**: 착지해서 단이 확정되면, 그 순간
  `PlayScoreBounce` 코루틴이 **이번 점프가 실제로 공중에 떠 있던 시간**(이륙~착지,
  `minScoreBounceSeconds`~`maxScoreBounceSeconds` 사이로 clamp) 동안 캐릭터를 **그 단
  과일이 실제로 걸려 있는 높이(fruit의 world Y)에서 캐릭터 렌더 높이의 70%를 뺀 지점**까지
  깔끔하게
  튀어올렸다가 다시 내려놓는다(코코넛 깨기의 `PunchCoconut`과 같은 "이벤트 하나 = 고정 시간
  연출" 구조) — 캐릭터가 화면에서 움직이는 유일한 순간이다. 발(anchor) 기준을 과일 Y에
  그대로 맞추면 발이 그 자리까지 가면서 캐릭터 몸통 전체가 과일보다 훨씬 위로 튀어나가
  보이므로, 몸통 중앙(절반)보다 조금 더 아래인 손 언저리가 과일에 닿는 정도로(절반 + 20%p
  추가 = 70%) 빼서 보정한다(`characterFrameWidth * 900/600`로 캐릭터 렌더 높이를 근사,
  `PlayScoreBounce`의 `HeightSubtractRatio` 상수). 상승/하강 모두 등속이 아니라 이징을
  적용했다 — **올라갈 때**는 `EaseInOut`(느리게→빠르게→느리게, 구간 중앙이 가장 빠름),
  **내려갈 때**는 그 반대인 `EaseOutIn`(빠르게→느리게→빠르게, 정점을 떠날 땐 빠르게
  출발했다가 중간에 느려지고 착지 직전 다시 빨라짐)을 쓴다. 이징 곡선의 강도는
  `bounceEasePower`(기본 3, cubic)로 조절 — 값을 올릴수록 시작·정점 부근(올라갈 때)/
  정점·착지 부근(내려갈 때)에서 더 느려진다(2=quad, 4=quartic). 같은 단의 과일 스프라이트는
  `fruitEatSeconds`(0.2초) 동안
  원래 크기에서 0으로 줄어들며
  사라진다(먹힌 것으로 표현). 사라진 과일은 화면에 다시 나타나지 않다가, 그 플레이어가
  **다음 점프를 시작(이륙)하는 순간** 원래 크기로 다시 나타난다(착지 시점이 아니라 다음
  이륙 시점인 점에 주의 — 3번 섹션 상태 흐름 참고).
- **텍스트 피드백**: 과일 획득 시 즉시 "OO +점수!" 표시, 라운드 종료 시 승패 문구가 더 길게
  표시된 뒤 다음 라운드로 넘어간다.
- **사운드**: 미구현. TODO.

## 8. 조정 가능한 값

| 필드명 | 기본값 | 단위 | 의미 |
|---|---|---|---|
| `matchSeconds` | 30 | 초 | 라운드 제한시간 |
| `tierHeightThresholds` | `{0.2, 0.4, 0.75}` | 비율(몸통 길이 대비) | 낮은/중간/높은 단 판정 임계값(오름차순 고정, `vision-server main.py`로 실측) |
| `tierScores` | `{1, 3, 5}` | 점 | 각 단 획득 시 점수 |
| `resultDisplaySeconds` | 2.0 | 초 | 승패 문구 표시 후 다음 라운드로 넘어가기 전 대기 시간 |
| `fruitWidth` | 0.4 | 월드 유닛 | 과일 스프라이트 표시 폭 |
| `fruitEatSeconds` | 0.2 | 초 | 채점된 과일이 줄어들며 사라지는 연출 시간 |
| `scoreBounceSeconds` | 0.35 | 초 | 디버그 키(A/B/C)처럼 실제 점프 시간을 잴 수 없을 때만 쓰는 `PlayScoreBounce` 재생 시간 기본값 — 실제 착지 판정에서는 대신 이번 점프의 실측 공중 시간을 쓴다(아래 두 필드로 clamp) |
| `minScoreBounceSeconds` | 0.2 | 초 | 실측 공중 시간이 이보다 짧아도 최소 이만큼은 재생(너무 짧아 안 보이는 것 방지) |
| `maxScoreBounceSeconds` | 1.2 | 초 | 실측 공중 시간이 이보다 길어도 최대 이만큼만 재생(너무 오래 붕 떠 있는 것 방지) — **캐릭터가 뛰어오르는 높이를 조절하는 곳은 이 필드들이 아니라 "각 과일 소품의 Y 위치"(`p1Fruits`/`p2Fruits`, 9. 참고)다** |
| `bounceEasePower` | 3 | (거듭제곱) | `PlayScoreBounce`의 상승(`EaseInOut`)/하강(`EaseOutIn`) 이징 강도 — 클수록 시작·정점(상승)/정점·착지(하강) 부근에서 더 느려짐(2=quad, 3=cubic, 4=quartic) |
| `JumpHeightCalibrator.calibrationSeconds` | 1.5 | 초 | 엉덩이 중점 기준선을 수집하는 캘리브레이션 시간(P1/P2 각각) |

**쿨다운을 따로 두지 않는 이유**: 판정 자체가 프레임 단위가 아니라 "점프 하나당 착지
시점에 한 번"이므로, 애초에 같은 점프에서 여러 번 채점될 여지가 없다(단마다 따로 쿨다운을
둘 필요가 있었던 옛 실시간 판정 방식과 달리, 지금은 구조적으로 점프당 최대 1회로 제한됨).

**프레임 애니메이션 연결됨**: 관절 리깅 대신 `jump_front_N` 프레임을 점프 높이 비율에 맞춰
통째로 교체하는 방식으로 바뀌었다(`FrameAnimatedCharacter`, `FruitJumpGame.TickTree`에서
매 프레임 `SetProgress(height / 최고단 임계값)` 호출). 원본 6장(`jump_front_1~6`)은
대기→상승→정점→정점→하강→착지(거의 대기와 동일) 순의 왕복 애니메이션이라 5·6번은 1·2번과
높이가 겹친다 — `SetProgress`는 높이 하나로 프레임 인덱스를 고르는 방식이라 뒤쪽 하강
프레임까지 그대로 쓰면 점프 최고점에서 오히려 착지 자세가 나오는 문제가 있어, 코드에서
상승 구간인 앞 4장(`jump_front_1~4`, 대기→정점)만 오름차순으로 잘라 쓴다(`FruitJumpGame.
BuildTree`). 캐릭터가 서 있을 때 발이 캔버스 하단에서 살짝(약 50px) 떠 있게 그려져 있어서,
그만큼을 `characterFrameWidth` 비율로 환산해 아래로 당기는 보정(`yOffset`)도 같이
넣었다. 이전에 쓰던 게임 전용 5프레임 세트(`games/03_fruit_pick/animation/jump_1~5`)는
이 공용 세트로 교체되며 삭제했다.
씬을 Unity 에디터로 직접 열어 확인한 적은 없으므로(코드만으로 작업), **세로 위치가 기존
리깅 캐릭터와 어긋나 보이면** `FruitJumpGame`이 만드는 `FrameAnimation`라는 이름의 자식
오브젝트 위치를 손으로 살짝 조정할 것(코드가 매 프레임 덮어쓰지 않는 필드다).

## 10. 예외 / 엣지 케이스

- **캘리브레이션 미완료**: P1/P2 중 한쪽이라도 `IsCalibrated == false`면 매치 타이머와 점수
  판정이 전혀 시작되지 않는다(화면에는 "캘리브레이션 중 - 가만히 서 있으세요..." 안내가
  뜬다). 캘리브레이션 중 트래킹이 끊기면 그 사람은 기준선 수집이 진행되지 않아 끝나지 않는다.
  (단, 현재 코드는 `debugP1OnlyTest` 스위치가 켜져 있으면 P1만 캘리브레이션되어도 진행한다 —
  P2용 카메라 없이 P1 혼자 테스트할 때 쓰는 임시 스위치. 8번 표 참고.)
- **트래킹 끊김(`IsTracked == false`)**: `GetJumpHeight()`가 0을 반환해 캐릭터가 기준
  위치로 내려가고, 그 프레임은 착지 상태로 취급된다.
- **한 점프에서 여러 단을 통과**: 판정이 착지 시점에 `PeakHeight` 하나로만 이루어지므로,
  점프 도중 낮은 단·중간 단을 거쳐 높은 단까지 올라갔더라도 착지 후 채점되는 건 최종
  정점이 속한 단 하나뿐이다 — "한 점프 = 과일 하나"가 판정 구조상 항상 보장된다(1·3번
  섹션 참고). 별도의 잠금 로직이 필요 없다.
- **정확히 같은 높이로 여러 프레임 정체(진동)**: `PeakHeight`는 "엄격히 더 큰 값"일 때만
  갱신되므로(`height > tree.PeakHeight`), 같은 높이가 반복되거나 미세하게 낮아지는 프레임은
  갱신을 일으키지 않는다.
- **동점으로 시간 종료**: 무승부 처리(승자 없음으로 `MatchController`에 보고).

## 11. 공용 의존성

- `PoseInputHub` / `PoseStreamReceiver` — 입력팀 담당, [게임_구동방식_정리.md](../게임_구동방식_정리.md) 참고
- `JumpHeightCalibrator` — 이 게임 전용 유틸. 엉덩이 중점(`Joints.HipMid`) y좌표로 기준선을
  잡고 몸통 길이 대비 상승 비율을 계산(`GetJumpHeight`), 캘리브레이션 상태(`IsCalibrated`) 노출
- ~~`CavemanSilhouette`(+ `Assets/Prefabs/Caveman_P1.prefab`, `Caveman_P2.prefab`)~~ — 관절
  리깅 캐릭터는 프레임 애니메이션으로 완전히 대체되어 씬에서 제거했다. 이제 캐릭터는
  `FruitJumpGame`의 `p1Anchor`/`p2Anchor`(빈 `Transform`) 하나에 `FrameAnimatedCharacter`를
  붙여서 표현한다.
- `MatchController` — 라운드 진행/최종 점수 집계. 승자가 정해지는 순간 `ReportRoundResult(winner)`
  한 번, 이어서 `LoadNextRound()` 한 번만 호출하면 됨(`winner`는 `PlayerId?` — 무승부면 `null`)
- `ArtAssets` — 프롭/캐릭터/게임별 스프라이트 로더(`LoadProp`, `LoadCharacter`, `LoadFruitJump` 등)
- `HudWidgets` — HUD Canvas를 카메라 프레임에 맞추는 `ConfigureForGameCamera`, 이미지/텍스트 위젯 생성(`CreateImage`, `CreateText`)
