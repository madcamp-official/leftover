# 3. 점프해서 과일따기 (Fruit Jump)

> 코드: `Assets/Scripts/Minigames/FruitJump/FruitJumpGame.cs`, `FruitJumpHud.cs`,
> `Assets/Scripts/Common/JumpHeightCalibrator.cs`.
> 씬: `Assets/Scenes/FruitJump.unity`.

## 0. 한 줄 요약

각자 자기 나무에서 입을 벌린 채로 높이 뛸수록 더 높은(더 비싼) 과일을 딴다 — 상대와 자원
경쟁은 없고, 순전히 자기 점프 실력과 타이밍(입 벌림)만으로 점수를 쌓는 경주.

## 1. 플레이어가 하는 일

| 동작 | 결과 |
|---|---|
| 입을 벌린 채로 낮게 점프 | 낮은 단(사과) 판정 시도 — 성공하면 그 점프는 사과로 확정(더 높이 올라가도 추가 채점 없음) |
| 입을 벌린 채로 중간 높이 점프 | 중간 단(포도) 판정 시도 |
| 입을 벌린 채로 높이 점프 | 높은 단(파인애플) 판정 시도 |
| 입을 다문 채로 점프 | 그 순간 입이 다물어져 있으면 그 프레임은 실패 — 같은 점프 중 더 오르거나(또는 계속 그 높이에 머물며) 다시 벌리면 재시도 가능 |
| 한 점프 안에서 이미 한 과일을 땀 | 같은 점프에서는 더 낮거나 높은 다른 단을 지나가도 추가로 채점되지 않음(한 점프 = 과일 하나) |
| 점프 후 완전히 착지 | 방금 딴 과일이 다시 열리고(재수확 가능), 다음 점프를 새로 채점받을 수 있음 |

## 2. 입력 신호 (PoseInputHub API)

| 신호 | 메서드/필드 | 이 게임에서의 의미 |
|---|---|---|
| 점프 높이 | `JumpHeightCalibrator.GetJumpHeight()` | 캘리브레이션된 기준선 대비 상승 비율(몸통 길이 대비). 0 이상, 클수록 높이 뜬 것 |
| 입 벌림 | `state.IsMouthOpen()` | 해당 단에 처음 도달한 프레임에 참이어야 과일 획득 인정 |
| 트래킹 여부 | `state.IsTracked` | false면 그 프레임은 획득 판정 자체를 하지 않음(점프 높이는 계속 0 처리) |

`PlayerPoseState`는 `PoseInputHub.Instance.Get(PlayerId.P1 / P2)`로 얻는다. `JumpHeightCalibrator`는
씬에 P1/P2용으로 하나씩 배치되어 있고, 내부적으로 **엉덩이 중점(`Joints.HipMid`)** y좌표를
스스로 추적하며 `PoseInputHub`를 읽는다 — 이 게임 코드는 `GetJumpHeight()`만 호출하면 된다.

발목이 아니라 엉덩이 중점을 기준점으로 쓰는 이유: 점프 정점에서는 발이 카메라 프레임 하단에
가까워 잘리거나 포즈 추정이 흔들리기 쉽지만, 몸통 중심에 가까운 엉덩이는 상대적으로 프레임
안쪽에 남아 추정이 더 안정적이다. 다만 이것도 만능은 아니다 — 아래 "10. 예외 / 엣지 케이스"의
카메라 프레이밍 항목 참고.

## 3. 규칙 / 상태 흐름

P1과 P2는 완전히 독립된 나무를 가지며 서로 영향을 주지 않는다(같은 화면에서 동시에 진행).
각 플레이어는 게임 시작 시 한 번 캘리브레이션을 거친다.

핵심 원칙: **한 번의 점프(이륙~착지)당 과일은 정확히 하나만 채점된다.** 점프 도중 여러 단을
거쳐 올라가더라도, 그중 하나가 채점되는 순간 그 점프는 "끝난 것"으로 취급하고 착지할
때까지 더 이상 채점하지 않는다.

```
[캘리브레이션] --calibrationSeconds(1.5초)간 가만히 서서 엉덩이 중점 높이 수집--> [캘리브레이션 완료]
(둘 다 완료되기 전까지는 매치 타이머도, 점수 판정도 시작하지 않는다)

[착지 상태(땅)] --점프 높이가 tierHeightThresholds[0]*0.5 이상으로 상승(이륙)--> [공중 - 채점 가능]
[공중 - 채점 가능] --그 프레임에 도달한 가장 높은 단에서 IsTracked && IsMouthOpen() 충족--> 그 단 채점, 과일 사라짐 --> [공중 - 채점 완료(잠금)]
[공중 - 채점 가능] --단 임계값 미달이거나 입을 안 벌림--> [공중 - 채점 가능] 그대로 유지(다음 프레임에 재시도)
[공중 - 채점 완료(잠금)] --계속 공중에 있음--> 추가 채점 없이 그대로 유지
[공중 - 채점 가능 또는 채점 완료] --점프 높이가 tierHeightThresholds[0]*0.5 미만으로 하강(착지)--> [착지 상태(땅)]로 복귀. 이번 점프에서 과일을 먹었다면 그 과일을 다시 보이게 함(재수확 가능)
```

**단(tier) 판정 방법** — 매 프레임, 그 순간의 점프 높이 하나로 "가장 높은 단"을 고른다:

```
currentTier = -1
for i = 2 downto 0 (파인애플 -> 포도 -> 사과 순, 즉 높은 단부터):
    if height >= tierHeightThresholds[i]:
        currentTier = i
        break  # 가장 높은 단 하나만 고르고 더 낮은 단은 보지 않는다
```

예를 들어 `tierHeightThresholds = {0.15, 0.35, 0.55}`일 때 어떤 프레임의 `height = 0.40`이면
`currentTier = 1`(포도)이다 — `height`가 사과 임계값(0.15)도 넘었지만 그 프레임에서 사과는
후보에 오르지 않는다. 사과가 채점되려면 **그 이전 프레임에서 height가 0.15~0.35 사이였고
그 순간 입이 벌어져 있어야** 한다(아래 예시 참고).

**매 프레임 하는 일** (플레이어별로 독립):

1. `GetJumpHeight()`로 현재 점프 높이를 읽고, 그 값만큼 캐릭터를 화면에서 위로 띄워 보여준다
   (`jumpBounceHeight`로 스케일).
2. 높이가 `tierHeightThresholds[0] * 0.5` 미만이면 "착지 상태"로 본다. 이번 점프에서 과일을
   먹었다면(`ScoredThisJump == true`) 먹었던 과일을 다시 보이게 하고, 다음 점프를 위해
   `ScoredThisJump`를 `false`로 리셋한 뒤 이번 프레임은 종료(채점 없음).
3. 착지 상태가 아니고 이미 이번 점프에서 과일을 먹었다면(`ScoredThisJump == true`) 이번
   프레임은 아무것도 하지 않고 종료 — 착지 전까지 추가 채점 없음.
4. 위 "단 판정 방법"으로 `currentTier`를 계산한다. 어떤 단 임계값에도 못 미치면(`currentTier
   < 0`) 종료.
5. 트래킹 중이고 입이 벌어져 있으면(`IsTracked && IsMouthOpen()`) → 점수 획득
   (`+tierScores[currentTier]`), `ScoredThisJump = true`로 잠금, HUD/이벤트 텍스트 갱신, 그
   단의 과일 스프라이트가 줄어들며 사라짐(`fruitEatSeconds` 동안).
6. 조건을 만족하지 못하면(트래킹 끊김 또는 입을 안 벌림) 이번 프레임은 실패로 끝나지만
   `ScoredThisJump`는 갱신되지 않으므로, 같은 점프 안에서 다음 프레임에 입을 벌리면 그때의
   `currentTier`(그 시점의 최고 단)로 다시 시도할 수 있다.

**한 점프에서 여러 단을 통과하는 예시** (사과 0.15 / 포도 0.35 / 파인애플 0.55, 매 프레임
입을 벌리고 있다고 가정):

| 프레임 | height | currentTier | 결과 |
|---|---|---|---|
| N | 0.20 | 0(사과) | 사과 채점, 점수 획득, `ScoredThisJump=true` |
| N+1 | 0.40 | 1(포도) | `ScoredThisJump==true`라서 판정 자체를 건너뜀 — 포도 획득 안 됨 |
| N+2 | 0.58 | 2(파인애플) | 마찬가지로 건너뜀 |
| N+5 | 0.05 | - | 착지, 사과가 다시 나타나고 `ScoredThisJump=false`로 리셋 |

즉 상승 도중 입을 계속 벌리고 있으면 **가장 먼저 넘은 단이 그 점프의 결과로 고정**된다.
반대로 정점까지 입을 다물고 있다가 최고점 근처에서만 벌리면 그 순간의 `currentTier`(가장
높은 단)를 바로 노릴 수 있다 — "낮은 단을 스치듯 지나가고 정점에서 크게 벌려 높은 단을
노린다"는 플레이가 가능하고 의도된 것이다.

## 4. 승리 / 패배 조건

`matchSeconds`(기본 30초) 경과 시점에 각자의 누적 점수를 비교해 **더 많이 딴 쪽이 승리**한다.
정확히 같으면 무승부.

## 5. 화면 구도

- 카메라: `Orthographic Size = 4`.
- 배경: `image/games/fruit_jump/background/background.png` 한 장, 카메라 뷰를 꽉 채우는 나무 그림.
- 캐릭터: 화면 왼쪽에 P1, 오른쪽에 P2. 각자 자기 나무 앞에 서 있고, 점프 높이에 비례해
  실제로 화면에서 위로 튀어오른다(`jumpBounceHeight`, 점프 높이 1.0 = 몸통 길이만큼 뜸
  기준으로 튀어오르는 월드 유닛).
- 과일: 각 플레이어의 나무에 낮은/중간/높은 단 순서로 사과/포도/파인애플이 배치돼 있다
  (`p1Fruits`/`p2Fruits` 배열 순서가 곧 `tierHeightThresholds` 순서).

## 7. 연출 / 피드백

- **캐릭터 점프**: 점프 높이에 비례해 캐릭터가 실시간으로 위아래로 움직인다(물리 없이
  포즈 데이터 기반 위치 보정).
- **과일 획득**: 획득한 단의 과일 스프라이트가 `fruitEatSeconds`(0.2초) 동안 원래 크기에서
  0으로 줄어들며 사라진다(먹힌 것으로 표현). 사라진 과일은 화면에 다시 나타나지 않다가,
  그 플레이어가 착지(기준선 절반 미만으로 복귀)하는 순간 원래 크기로 다시 나타난다.
- **텍스트 피드백**: 과일 획득 시 즉시 "OO +점수!" 표시, 라운드 종료 시 승패 문구가 더 길게
  표시된 뒤 다음 라운드로 넘어간다.
- **사운드**: 미구현. TODO.

## 8. 조정 가능한 값

| 필드명 | 기본값 | 단위 | 의미 |
|---|---|---|---|
| `matchSeconds` | 30 | 초 | 라운드 제한시간 |
| `tierHeightThresholds` | `{0.15, 0.35, 0.55}` | 비율(몸통 길이 대비) | 낮은/중간/높은 단 판정 임계값(오름차순 고정) |
| `tierScores` | `{1, 3, 5}` | 점 | 각 단 획득 시 점수 |
| `resultDisplaySeconds` | 2.0 | 초 | 승패 문구 표시 후 다음 라운드로 넘어가기 전 대기 시간 |
| `fruitWidth` | 0.4 | 월드 유닛 | 과일 스프라이트 표시 폭 |
| `jumpBounceHeight` | 1.5 | 월드 유닛 | 점프 높이 1.0(몸통 길이만큼 뜸) 기준 캐릭터가 튀어오르는 거리 |
| `fruitEatSeconds` | 0.2 | 초 | 채점된 과일이 줄어들며 사라지는 연출 시간 |
| `JumpHeightCalibrator.calibrationSeconds` | 1.5 | 초 | 엉덩이 중점 기준선을 수집하는 캘리브레이션 시간(P1/P2 각각) |

**쿨다운을 따로 두지 않는 이유**: 과거 설계는 단마다 별도 쿨다운(`tierCooldowns`)으로 너무
빠른 재채점을 막았지만, "한 점프당 과일 하나" 잠금(`ScoredThisJump`)이 이미 착지 전까지
추가 채점을 완전히 막으므로 쿨다운이 중복 안전장치였다. 착지 자체가 최소 대기 시간 역할을
한다고 보고 제거했다.

프레임 스프라이트 재생"으로 바꾸는 결정이 먼저 필요하다(여러 미니게임에 걸친 결정 — 별도
논의 필요, [01_돌던지기.md](01_돌던지기.md)의 같은 이슈 참고).

## 10. 예외 / 엣지 케이스

- **캘리브레이션 미완료**: P1/P2 중 한쪽이라도 `IsCalibrated == false`면 매치 타이머와 점수
  판정이 전혀 시작되지 않는다(화면에는 "캘리브레이션 중 - 가만히 서 있으세요..." 안내가
  뜬다). 캘리브레이션 중 트래킹이 끊기면 그 사람은 기준선 수집이 진행되지 않아 끝나지 않는다.
  캘리브레이션은 엉덩이 중점만 보고 입은 보지 않으므로, 이 단계 자체는 머리가 프레임 밖으로
  나가도 영향받지 않는다(가만히 서 있는 자세라 애초에 머리가 나갈 일도 적다).
- **점프 정점에서 머리가 카메라 프레임 밖으로 나감**: 채점에는 입 벌림(`IsMouthOpen`)이
  필요한데, 이 값은 얼굴 인식 결과라 몸 전체 트래킹(`IsTracked`)과 별도로 흔들릴 수 있다.
  카메라를 너무 타이트하게(예: 가슴 위만) 잡아두면 높이 점프했을 때 머리가 잘려 그 순간
  `IsMouthOpen`이 신뢰할 수 없는 값을 반환하거나 `IsTracked`가 꺼질 수 있다 — **설치 시
  카메라 프레이밍은 가장 높은 단(`tierHeightThresholds`의 최댓값)까지 뛰었을 때도 정수리가
  프레임 안에 남도록 여유를 두어야 한다.** 이는 코드로 해결할 수 없는 물리적 설치 요구사항이므로
  플레이테스트 때 반드시 확인할 것(13. TODO 참고).
- **트래킹 끊김(`IsTracked == false`)**: `GetJumpHeight()`가 0을 반환해 캐릭터가 기준
  위치로 내려가고, 어떤 단도 채점되지 않는다(과일 미획득으로 처리, 감점은 없음). 이미 그
  점프에서 과일을 먹은 상태였다면(`ScoredThisJump == true`) 트래킹이 끊긴 동안에도 그 상태는
  유지되다가, `GetJumpHeight()`가 0(=착지 판정 임계값 미만)이 되는 순간 착지로 처리되어
  과일이 정상적으로 복구된다.
- **한 점프에 여러 단을 동시에·연속으로 통과**: 그 프레임에는 가장 높은 단 하나만
  `currentTier` 후보가 되고, 일단 어느 한 단이 채점되면(`ScoredThisJump = true`) 같은
  점프에서는 더 높은 단을 지나가도 추가로 채점되지 않는다 — "한 점프 = 과일 하나"가 항상
  보장된다(3번 섹션의 예시 참고).
- **입을 늦게 벎(그 프레임에는 다물고 있었음)**: 그 단은 이번 프레임 판정에서 실패로 끝나지만
  `ScoredThisJump`는 갱신되지 않으므로, 같은 점프 중 다음 프레임에 입을 벌리면(높이가 여전히
  어떤 단 이상이면) 그 시점의 `currentTier`로 재시도할 수 있다.
- **동점으로 시간 종료**: 무승부 처리(승자 없음으로 `MatchController`에 보고).

## 11. 공용 의존성

- `PoseInputHub` / `PoseStreamReceiver` — 입력팀 담당, [GETTING_STARTED.md](../../GETTING_STARTED.md) 참고
- `JumpHeightCalibrator` — 이 게임 전용 유틸. 엉덩이 중점(`Joints.HipMid`) y좌표로 기준선을
  잡고 몸통 길이 대비 상승 비율을 계산(`GetJumpHeight`), 캘리브레이션 상태(`IsCalibrated`) 노출
- `CavemanSilhouette` (+ `Assets/Prefabs/Caveman_P1.prefab`, `Caveman_P2.prefab`) — 캐릭터 리깅
- `MatchController` — 라운드 진행/최종 점수 집계. 승자가 정해지는 순간 `ReportRoundResult(winner)`
  한 번, 이어서 `LoadNextRound()` 한 번만 호출하면 됨(`winner`는 `PlayerId?` — 무승부면 `null`)
- `ArtAssets` — 프롭/캐릭터/게임별 스프라이트 로더(`LoadProp`, `LoadCharacter`, `LoadFruitJump` 등)
- `HudWidgets` — HUD Canvas를 카메라 프레임에 맞추는 `ConfigureForGameCamera`, 이미지/텍스트 위젯 생성(`CreateImage`, `CreateText`)

## 12. 구현 완료 기준 (Acceptance Checklist)

- [ ] 양쪽 캘리브레이션이 끝나기 전에는 매치 타이머와 점수 판정이 시작되지 않는다
- [ ] 입을 벌린 채로 어떤 단 높이를 처음 넘으면 해당 단 점수가 정확히 1회 가산된다
- [ ] 입을 다문 채로 단을 넘으면 그 시도는 실패 처리되고 점수가 오르지 않지만, 같은 점프
      안에서 이후 프레임에 입을 벌리면 재시도된다
- [ ] 한 점프에서 이미 한 단이 채점되면, 착지하기 전까지는 같은 점프에서 더 낮거나 높은
      다른 단이 추가로 채점되지 않는다(한 점프 = 과일 하나)
- [ ] 착지(기준선 높이의 절반 미만)해야 다음 점프에서 새로 채점받을 수 있다
- [ ] 과일을 획득하면 해당 과일 스프라이트가 화면에서 사라지고, 그 플레이어가 착지하는
      순간 다시 나타난다
- [ ] 점프 높이만큼 캐릭터가 화면에서 실제로 튀어오른다
- [ ] `matchSeconds` 경과 시 정확히 더 많이 딴 쪽이 승자로 `MatchController`에 보고된다
- [ ] HUD 점수/타이머가 매 프레임 정확한 값으로 갱신된다
- [ ] 라운드 종료 후 `resultDisplaySeconds` 뒤 자동으로 다음 씬으로 넘어간다
