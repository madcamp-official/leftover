## 0. 한 줄 요약

손을 든 채로 있으면 자동으로 돌이 계속 날아간다 — 어느 손을 드느냐로 조준을, 머리를
어느 쪽으로 기울이느냐로 회피를 계속 바꿔가는 실시간 공방.

## 1. 플레이어가 하는 일

| 동작 | 결과 |
|---|---|
| 오른손 들기 | 그 손이 들린 채로 발사 타이밍이 될 때, 상대의 **오른쪽**을 조준 |
| 왼손 들기 | 상대의 **왼쪽**을 조준 |
| **양손을 동시에 들고 있기** | **더 먼저 들기 시작한 손** 쪽으로 조준(나중에 든 손은 무시) — 오른손이 우선이 아니라 "시간상 먼저"가 기준. 두 손이 정확히 같은 프레임에 동시에 들리기 시작한 경우에만 오른손으로 처리(사실상 발생 안 함) |
| 손을 완전히 내림 | 발사 대기 진행이 취소됨 — 다시 들면 처음부터 다시 기다려야 함(중간부터 이어지지 않음) |
| (상대 공격을 받는 쪽) 머리를 좌/우로 기울임 | 그 순간 자신을 조준한 방향과 기울인 방향이 같으면 회피 |
| (상대 공격을 받는 쪽) 머리를 안 기울이거나 살짝만 기울임 | 명중 처리 |

## 2. 입력 신호 (PoseInputHub API)

| 신호 | 메서드/필드 | 이 게임에서의 의미 |
|---|---|---|
| 오른손 들림 | `state.IsHandRaised(rightHand: true)` | 참이면 오른쪽 조준 후보 |
| 왼손 들림 | `state.IsHandRaised(rightHand: false)` | 참이면 왼쪽 조준 후보 |
| 머리 기울기 | `state.HeadTiltRatio()` | 아래 설명 참고 |
| 트래킹 여부 | `state.IsTracked` | false면 그 사람은 이번 판정에서 열외 (10장 "예외" 참고) |

**머리 기울기(`HeadTiltRatio`)의 정확한 계산 방식**: 코 좌표(`nose`)가 "엉덩이 중심
(`leftHip`과 `rightHip`의 중점)을 지나는 수직 기준선"에서 좌우로 얼마나 벗어났는지를,
몸통 길이(어깨 중점~엉덩이 중점 거리)로 정규화한 값이다.

```
HeadTiltRatio = (nose.x - hipMid.x) / torsoLength
```

즉 "머리 좌표가 몸통 축 기준선에서 얼마나 벗어났는지"를 재는 것이지, 목이나 어깨 관절의
실제 회전각을 재는 게 아니다. 이 방식을 쓰는 이유: 머리(코)는 목~어깨 구조상 몸을 살짝만
기울여도 기준선에서 크게 벗어나는 지점이라(지렛대 원리 — 회전 중심인 엉덩이에서 가장 먼
지점일수록 같은 각도라도 옆으로 이동하는 거리가 커진다), 작은 움직임도 민감하게 잡을 수
있다. 값의 부호: 화면 오른쪽으로 기울면 양수, 왼쪽이면 음수(카메라가 거울모드라 사용자의
실제 좌우와 화면 좌우가 일치한다).

## 3. 규칙 / 상태 흐름

이 게임은 명시적 상태 머신 없이, 플레이어별로 독립된 **"발사 타이머"**만 돌아간다(P1용
하나, P2용 하나 — 서로 완전히 독립적으로, 동시에 진행됨).

### 용어 정리: "발사 타이머" vs "발사 타이밍"

이 둘은 다른 걸 가리키는 말이라 헷갈리기 쉽다.

- **발사 타이머** = 계속 흐르는 값(스톱워치) 그 자체. 게임 내부에서 플레이어 한 명당
  실수(float) 변수 하나로 존재하며, 매 프레임 조금씩 증가하다가 특정 값에 도달하면 0으로
  되돌아가는 걸 반복한다. "상태"가 아니라 "숫자"다.
- **발사 타이밍** = 그 숫자가 목표값(`fireIntervalSeconds`)에 **막 도달한 바로 그
  프레임**. 돌이 실제로 나가는 건 오직 이 프레임뿐이고, 그 사이(충전되는 동안)에는 아무
  일도 일어나지 않는다. "언제 쏠지"를 가리키는 시점 개념이다.

비유하면: 발사 타이머는 전자레인지의 "남은 시간 카운트다운" 숫자, 발사 타이밍은 그
숫자가 0이 되어 "땡!" 소리가 나는 순간이다.

### 왜 이런 방식인가 (단발 트리거가 아니라 자동 충전식인 이유)

손을 들 때마다 한 발씩 나가는 "단발 트리거" 방식이 아니라, 손을 든 채로 있으면 알아서
계속 발사되는 "자동 충전식"으로 만든 이유: 포즈 인식은 정확히 "이 프레임에 손이 막
올라갔다"를 잡아내기 어렵다(카메라 프레임레이트나 인식 흔들림 때문에 "든 순간"이 애매하게
걸릴 수 있음). 대신 "지금 손이 들려 있는가/아닌가"라는 훨씬 안정적인 상태만 보고, 발사
타이밍은 게임이 자체적으로 정한 일정한 주기로 스스로 만들어내는 쪽이 훨씬 안정적으로
동작한다.

### 프레임 단위로 정확히 어떻게 계산되는가 (의사코드)

Unity의 `Update()`는 매 프레임(대략 초당 수십~백여 번) 호출되고, 그때마다 직전 프레임과의
시간 간격이 `Time.deltaTime`(초 단위, 보통 0.01~0.02 정도의 아주 작은 값)으로 주어진다.
발사 타이머는 이 값을 계속 더해나가는 누산기다.

```
// 매 프레임(Update) 실행됨. player 1명당 이 로직이 독립적으로 한 번씩 돈다.
if (오른손도 안 들려있고 왼손도 안 들려있음) {
    타이머 = 0                       // 손을 놓으면 즉시 리셋하고 더 이상 안 늘어남
    return
}

타이머 += Time.deltaTime             // 손이 들려 있는 프레임마다 아주 조금씩 증가

if (타이머 < fireIntervalSeconds) {
    return                            // 아직 안 찼음 - 이번 프레임은 "충전 중", 아무 일 없음
}

// 여기 도달한 이 프레임이 바로 "발사 타이밍"이다.
타이머 = 0                            // 즉시 리셋 - 같은 프레임에 두 번 발사되지 않게
조준방향 = (지금 이 순간의 오른손/왼손 상태로 결정)   // 1장/아래 "발사 판정" 참고
... 명중/회피 판정 실행 ...
```

즉 `fireIntervalSeconds`가 1초라고 해서 "정확히 1.000000초"에 딱 맞춰 발사되는 게
아니라, 타이머가 1초를 **넘어서는 첫 프레임**에 발사된다(프레임 간격만큼의 오차가 있을
수 있음 — 초당 60프레임이면 최대 약 0.016초 정도 늦게 발사될 수 있다는 뜻인데, 사람이
체감하기엔 무의미한 차이다).

### 시간 순서 예시

P1이 계속 오른손만 들고 있다고 가정, `fireIntervalSeconds = 1초`:

```
0.0초  P1이 오른손을 든다 → 타이머 시작(0초부터 누적)
1.0초  타이머가 1초 도달 → 이 프레임이 발사 타이밍 → 돌 1발 발사(오른쪽 조준) → 타이머 0으로 리셋
2.0초  타이머가 다시 1초 도달 → 발사 타이밍 → 돌 2발째 발사 → 리셋
2.6초  P1이 오른손을 왼손으로 바꿔 든다(타이머는 안 끊김 — 여전히 "손이 들려있는 상태"이므로
       계속 누적되고 있었음. 지금은 1.6초 누적된 상태)
3.0초  타이머가 1초 도달(2.0초 이후로 1초 지남) → 발사 타이밍 → 돌 3발째 발사,
       **이번엔 왼쪽 조준**(발사 타이밍인 이 순간의 손 상태를 보므로 - 충전 중간에 바꿔
       든 게 그대로 반영됨)
3.5초  P1이 손을 완전히 내린다 → 타이머가 즉시 0으로 리셋되고 멈춤(더 이상 안 늘어남 -
       이때는 아직 0.5초밖에 안 찬 상태였으므로 그 0.5초는 그냥 사라짐)
4.2초  P1이 다시 오른손을 든다 → 타이머가 **0부터 다시** 시작(3.5~4.2초 동안 손을 안 든
       시간은 셈에 포함 안 됨 - 중간에 손을 내렸다 들면 이어서 세지 않고 완전히 처음부터)
5.2초  타이머가 1초 도달 → 발사 타이밍 → 돌 4발째 발사
```

핵심은 세 가지다:
1. 타이머는 "손이 하나라도 들려 있는 동안"에만 흐르고, 완전히 손을 내리는 순간 즉시
   0으로 리셋된다(진행 중이던 충전은 버려짐 — 이어하기 없음).
2. 발사 타이밍(타이머가 다 찬 그 프레임)의 손 상태로 조준 방향이 정해진다. 충전 시작
   시점의 손이 아니라 **발사되는 순간의** 손을 본다 — 그래서 충전 도중에 손을 바꿔 들면
   다음 발사의 조준도 따라 바뀐다.
3. 손을 계속 들고만 있으면 별도 조작 없이 `fireIntervalSeconds` 간격으로 영원히
   발사가 반복된다 — 이게 "기관총식 연속 발사"라고 부르는 이유다.

### 발사 판정 실행 시점에 하는 일 (그 프레임에서 즉시, 순서대로)

1. 그 순간 오른손만 들려 있으면 조준 방향 = 오른쪽, 왼손만 들려 있으면 왼쪽. **양손 다
   들려 있으면** 두 손 중 "더 먼저 들리기 시작한" 쪽을 조준 방향으로 쓴다(1장 참고).
2. 상대가 트래킹되고 있으면: 상대의 `HeadTiltRatio()`를 읽어
   - `dodgeTiltThreshold`보다 크면 → 회피 방향 = 오른쪽
   - `-dodgeTiltThreshold`보다 작으면 → 회피 방향 = 왼쪽
   - 그 사이(거의 안 기울임)면 → 회피 방향 없음
3. 상대가 트래킹 안 되고 있으면 → 무조건 명중 처리(회피 불가능한 것으로 간주).
4. 조준 방향과 회피 방향이 **같으면** 회피, **다르면(또는 회피 방향이 없으면)** 명중.
5. 명중이면 맞은 사람의 누적 피격 수를 올리고 체력을 깎은 뒤 HUD/표정 갱신, 회피면 텍스트만
   표시.
6. 던진 사람 쪽에서 맞은 사람 쪽으로 돌 하나가 시각적으로 날아간다(연출, 판정에는 영향 없음).
7. 맞은 사람의 체력이 0이 되면 그 즉시 라운드가 끝난다(4장 참고). 아니면 타이머를 0으로
   되돌리고 같은 사람에 대해 다시 1번부터.

P1의 타이머/판정과 P2의 타이머/판정은 서로 완전히 독립이다 — 두 사람이 동시에 서로를
맞힐 수 있다.

## 4. 승리 / 패배 조건

각자 체력(`maxHealth`, 기본 **10**)을 갖고 시작한다. 맞을 때마다 자신의 체력이 1씩
줄어든다.

- **즉사(Sudden Death)**: 누군가의 체력이 0이 되는 순간, 제한시간이 남아있어도 그 즉시
  라운드가 끝나고 **상대가 승리**한다.
- **시간 종료**: `matchSeconds`(기본 30초)가 다 될 때까지 아무도 체력 0이 안 됐으면, 그
  시점의 체력을 비교해 **더 많이 남은(=더 적게 맞은) 쪽이 승리**한다. 정확히 같으면
  무승부.

(체력은 "맞은 횟수"의 반대 표현일 뿐이다 — 맞은 횟수가 곧 잃은 체력이므로, 내부적으로는
맞은 횟수 하나만 세고 체력 = `maxHealth - 맞은 횟수`로 계산한다.)

## 5. 화면 구도

### 배경 에셋 경로 규칙 (모든 미니게임 공통, 템플릿에도 반영)

모든 미니게임의 배경 원본은 항상 `image/games/(게임 폴더명)/background/`에 둔다. 이
게임은 `image/games/stone_throw/background/background.png` 한 장(→ Unity
`Assets/Resources/StoneThrow/background.png`)이다.

한 장, 카메라 뷰를 꽉 채움.
-화면을 좌/우로 절반씩 나눈다. **왼쪽 절반 = P1이 상대(P2)를 마주보는 시점, 오른쪽 절반 =
P2가 상대(P1)를 마주보는 시점**이다(둘 다 하나의 공유 화면에 동시에 보임 — 실제로 화면이
물리적으로 두 대인 게 아니라, 한 화면 안에서 왼쪽 구역/오른쪽 구역으로 나뉜다는 뜻).

각 절반 안의 배치:

| 위치 | 왼쪽 절반(P1 시점) | 오른쪽 절반(P2 시점) |
|---|---|---|
| 화면 중단 살짝 위 | **P2의 앞모습**, 와이드샷(전신이 보이는 먼 화각) | **P1의 앞모습**, 와이드샷 |
| 화면 하단 우측 | **P1의 뒷모습**, 바스트샷(상체 클로즈업) | **P2의 뒷모습**, 바스트샷 |

즉 왼쪽 절반은 "내가(P1) 상대(P2)를 정면으로 겨누고 있고, 내 뒷모습이 화면 앞쪽 아래
구석에 걸쳐 보이는" 오버더숄더 구도다. 오른쪽 절반은 그 반대(P2 시점)로 대칭.

**원근감은 새 배경 그림이 아니라 배치로 만든다**: 기존 배경(`background.png`) 한 장을
그대로 쓰되, **하단(발밑 지면/바닥에 가깝게)·중단(와이드샷 인물이 서는 자리)·상단(하늘/먼
배경)** 세 구역에 각 요소(캐릭터·소품)를 서로 다른 높이·크기로 배치해서 "앞에서 던지는
것처럼" 원근감을 낸다 — 새로 그려야 할 배경 이미지는 없다.

## 10. 예외 / 엣지 케이스

- **한쪽이 트래킹 안 됨(`IsTracked == false`)**: 그 사람은 손을 들어도 발사 타이머가 진행되지
  않는다(공격 불가). 반대로 그 사람이 "회피 대상"일 때는 회피 불가능한 것으로 보고 무조건
  명중 처리한다 — 즉 트래킹이 끊기면 공격은 못 하지만 방어도 못 한다.
- **양쪽이 정확히 같은 프레임에 서로를 명중**: 문제 없음 — 두 타이머가 독립적이라 각자
  판정되고 누적치에 정상 반영된다. 둘 다 그 판정으로 체력이 0이 되면(동시 즉사) 이후
  프레임에서 시간 종료 로직과 마찬가지로 먼저 처리되는 쪽이 승자로 보고된다(사실상 코드
  실행 순서상 P1 판정이 먼저 처리됨 — 극히 드문 경우라 우선순위를 더 정교하게 다듬을
  필요는 낮음).
- **양손을 정확히 같은 프레임에 동시에 들기 시작**: "먼저 든 손" 비교가 무승부이므로
  오른손으로 처리(1장).
- **동점으로 시간 종료**: 무승부 처리(승자 없음으로 `MatchController`에 보고).
- **손을 든 채로 라운드가 끝남**: 다음 라운드로 넘어가므로 별도 정리 로직 불필요(씬 전환 시
  이 게임의 타이머 상태는 자동으로 사라짐).
