# 1. 돌던지기 (Stone Throw)

> 목표 기획 사양. 구현 코드: `Assets/Scripts/Minigames/StoneThrow/StoneThrowGame.cs`,
> `StoneThrowHud.cs`. 씬: `Assets/Scenes/StoneThrow.unity`.
>
> 이 문서의 규칙이 돌던지기의 기준이다. 기존 코드에 남은 체력제·관절 리깅 기반 투척·
> 손을 들어야 진행되는 발사 타이머는 이 사양에 맞게 교체해야 한다.

## 0. 한 줄 요약

양쪽 플레이어에게 일정 간격으로 발사 이벤트가 찾아오며, 그 순간 한쪽 손만 들어 돌의 방향을
정하고 머리를 좌우로 기울여 상대 돌의 목표 위치를 피한다. 제한시간 동안 더 많이 명중시킨
사람이 승리한다.

## 1. 핵심 규칙

- P1과 P2 모두 게임 시작부터 종료까지 `fireIntervalSeconds` 간격으로 발사 이벤트가 계속
  트리거된다.
- 발사 이벤트 순간의 손 상태만 읽는다. 이벤트 사이에 손을 언제 들었는지는 판정하지 않는다.
- 오른손만 들었으면 돌을 오른쪽으로, 왼손만 들었으면 왼쪽으로 던진다.
- 양손을 들었거나 두 손을 모두 내렸으면 그 이벤트에서는 돌을 던지지 않는다.
- 돌을 던질 때는 관절 파츠를 실시간으로 회전하지 않고, 미리 제작한 돌던지기 캐릭터
  애니메이션 프레임을 순서대로 재생한다.
- 플레이어에게 체력은 없다. 제한시간이 끝날 때까지 게임이 중단되지 않는다.
- 제한시간 종료 시 상대에게 돌을 더 많이 맞힌 플레이어가 승리한다. 명중 수가 같으면
  무승부다.

## 2. 시작 전 캘리브레이션

두 플레이어는 각자 한 대의 카메라 앞에서 별도로 캘리브레이션한다.

### 로딩 화면에서 진행

캘리브레이션은 별도 로딩 화면에서 진행한다. 이 화면은 게임 씬이 준비되는 동안 단순히
기다리는 화면이 아니라, 양쪽 플레이어의 입력 준비 상태를 확인하는 시작 게이트다.

- 상단에 돌던지기 게임 로고를 표시한다.
- `image/screens/loading/`의 기존 로딩 배경 중 하나를 매번 랜덤으로 선택한다.
- 본인의 실시간 카메라 영상을 공통 카메라 프레임 안에 크게 보여준다.
- `얼굴과 양손이 모두 보이도록 차렷 자세로 서 주세요!`라는 안내를 표시한다.
- 공통 원형 로딩 링 PNG 하나를 Unity에서 회전시켜 인식 진행 중임을 보여준다.
- 본인의 `자세 인식 중`/`준비 완료` 상태를 표시한다.
- 상대방의 `준비 중`/`준비 완료` 상태를 네트워크 ready 값에 따라 표시한다.
- 화면 하단에는 짧고 웃긴 팁 문구를 2~3초 간격으로 순환 표시한다.
- 양쪽이 모두 준비 완료될 때까지 로딩 화면을 유지한다.

공통 에셋은 `image/common/ui/loading/`, 게임별 구성과 배치 예시는
`image/games/stone_throw/loading/README.md`와
`image/games/stone_throw/loading/previews/loading_calibration_preview.png`를 기준으로 한다.

### 올바른 준비 자세

- 얼굴 전체가 카메라 프레임 안에 있어야 한다.
- 차렷 자세로 선다.
- 양손이 모두 카메라 프레임 안에 보여야 한다.
- 얼굴과 양손의 필수 랜드마크가 일정 시간 안정적으로 추적되어야 한다.

### 시작 게이트

1. P1과 P2가 각자 캘리브레이션을 시작한다.
2. 각 카메라는 중립 머리 위치, 몸통 기준선, 손을 든 상태를 구분할 기준을 수집한다.
3. 조건을 만족한 플레이어만 `Ready` 상태가 된다.
4. 한쪽만 준비된 경우 게임은 시작하지 않고 다른 플레이어를 기다린다.
5. 양쪽 모두 `Ready`가 된 뒤 카운트다운을 표시하고, 카운트다운 종료와 함께 제한시간과
   발사 이벤트 타이머를 시작한다.

캘리브레이션 중 얼굴이나 한쪽 손이 프레임 밖으로 나가면 해당 플레이어의 수집을 일시
중단하거나 다시 시작한다. 캘리브레이션 완료 상태는 양쪽 ready-check로 동기화한다.

## 3. 모션 인식 입력

| 입력 | 판정 | 게임 결과 |
|---|---|---|
| 오른손만 들기 | 오른손 들림, 왼손 내려감 | 다음 발사 이벤트에서 오른쪽으로 발사 |
| 왼손만 들기 | 왼손 들림, 오른손 내려감 | 다음 발사 이벤트에서 왼쪽으로 발사 |
| 양손 들기 | 양손 모두 들림 | 해당 발사 이벤트 취소 |
| 양손 내리기 | 양손 모두 내려감 | 해당 발사 이벤트 취소 |
| 고개를 오른쪽으로 기울이기 | `HeadSide = Right` | 캐릭터를 오른쪽 회피 위치에 배치 |
| 고개를 왼쪽으로 기울이기 | `HeadSide = Left` | 캐릭터를 왼쪽 회피 위치에 배치 |

손 상태와 머리 방향은 카메라에서 계속 갱신하지만, 손 상태는 발사 이벤트가 발생한 정확한
시점의 값만 사용한다.

## 4. 좌우 회피 상태

캐릭터의 위치 상태는 `Left`와 `Right` 두 가지뿐이다. `Center` 상태는 존재하지 않는다.

- 고개가 오른쪽이면 캐릭터가 오른쪽 고정 위치로 이동한다.
- 고개가 왼쪽이면 캐릭터가 왼쪽 고정 위치로 이동한다.
- 중립 근처에서 인식값이 흔들릴 때는 직전의 안정된 좌/우 상태를 유지한다.
- 캘리브레이션 직후 최초 상태도 반드시 좌/우 중 하나로 확정한 뒤 게임을 시작한다.
- 좌우 전환에는 작은 히스테리시스나 유지 시간을 적용해 한 프레임마다 위치가 떨리지 않게
  한다. 이 보정은 `Center` 상태를 추가하는 것이 아니라 마지막 좌/우 선택을 유지하는 방식이다.

명중 판정은 발사 방향과 피격 대상의 위치를 비교한다.

| 돌의 목표 방향 | 상대 위치 | 결과 |
|---|---|---|
| Left | Left | 명중 |
| Left | Right | 회피 |
| Right | Right | 명중 |
| Right | Left | 회피 |

즉 돌이 날아오는 목표 위치와 반대쪽으로 고개를 기울여 캐릭터를 이동시키면 피할 수 있다.

## 5. 발사 이벤트와 투척 애니메이션

발사 이벤트 타이머는 손 상태와 무관하게 계속 흐른다. 양쪽 플레이어는 각각 같은 주기의
이벤트를 가지며, 같은 프레임에 동시에 발사될 수도 있다.

```text
게임 시작
  → P1/P2 발사 타이머 계속 진행
  → fireIntervalSeconds 도달
  → 그 순간의 손 상태 스냅샷 확인
      오른손만 듦: 오른쪽 투척 애니메이션 + 오른쪽 돌 생성
      왼손만 듦: 왼쪽 투척 애니메이션 + 왼쪽 돌 생성
      양손/무손: 애니메이션과 돌 생성 없음
  → 타이머를 0으로 되돌림
  → 제한시간이 남아 있으면 같은 과정 반복
```

한 손만 든 유효 발사에서는 다음 순서로 처리한다.

1. 손 방향에 대응하는 캐릭터 애니메이션을 재생한다.
2. 애니메이션의 릴리즈 프레임에 돌 투사체를 생성한다.
3. 발사 이벤트 시각의 상대 `HeadSide`를 기준으로 명중 또는 회피를 확정한다.
4. 돌은 해당 좌/우 목표점까지 날아가는 연출을 재생한다.
5. 명중이면 공격자의 명중 수를 1 올리고 피격 얼굴 오버레이를 표시한다.

판정과 시각 연출은 분리한다. 네트워크나 프레임 재생이 조금 늦어져도 명중 판정에는 발사
이벤트 시각에 저장한 손 상태와 상대 머리 방향을 사용한다.

## 6. 캐릭터 애니메이션

돌던지기 동작은 다음 이미지 세트를 사용한다.

```text
image/characters/character{1,2}/games/01_stone_throw/animation/
├── right_hand/       오른손 투척 정면
├── left_hand/        왼손 투척 정면
├── right_hand_back/  오른손 투척 후면
└── left_hand_back/   왼손 투척 후면
```

- 왼쪽 화면과 오른쪽 화면의 상대 앞모습에는 `right_hand` 또는 `left_hand`를 재생한다.
- 화면 전경에서 자기 뒷모습을 보여줄 경우에는 대응하는 `*_back` 세트를 재생한다.
- 각 캐릭터의 네 세트는 모두 `stone_throw_1.png`부터 `stone_throw_6.png`까지 순서대로
  재생하고 기본 대기 이미지로 복귀한다.
- 돌 이미지는 캐릭터 프레임에 포함하지 않는다. 릴리즈 시점에 별도 투사체 에셋을 생성한다.
- 두 캐릭터 모두 6프레임이며 같은 총 재생 시간과 프레임 간격을 사용한다.
- 던지는 동안에도 머리 인식은 계속되며, 회피 위치 상태는 독립적으로 갱신된다.

## 7. 피격 표정

돌에 맞으면 해당 캐릭터의 `grimacing.png`를 기존 얼굴보다 높은 렌더링 레이어에 표시해
기존 얼굴을 완전히 덮는다.

- 피격 즉시 찡그린 얼굴 오버레이를 켠다.
- `hitFaceDisplaySeconds` 동안 유지한 뒤 오버레이를 끈다.
- 연속으로 맞으면 표시 시간을 마지막 피격 시점부터 다시 센다.
- 원래 얼굴 이미지는 제거하지 않고 아래에 유지한다.
- 앞모습 캐릭터에만 얼굴이 보이므로, 후면 캐릭터에는 별도 얼굴 오버레이를 표시하지 않는다.

에셋 경로:

- `image/characters/character1/games/01_stone_throw/expressions/grimacing.png`
- `image/characters/character2/games/01_stone_throw/expressions/grimacing.png`

## 8. 승리 / 패배 조건

- 게임에는 체력, 체력바, 체력 0 즉시 종료가 없다.
- `matchSeconds`가 끝날 때까지 발사 이벤트와 명중 판정을 계속한다.
- P1이 P2에게 맞힌 횟수와 P2가 P1에게 맞힌 횟수를 비교한다.
- 더 많이 맞힌 플레이어가 승리한다.
- 두 명중 수가 같으면 무승부다.

HUD의 기존 `맞은 돌` 숫자를 유지한다면 각 플레이어가 맞은 횟수를 표시한다. 승패 계산에서는
상대의 `맞은 돌` 수가 곧 자신의 명중 수다.

## 9. 화면 구도와 배경

배경은 `image/games/stone_throw/background/background.png`를 사용한다. 한 장 안에서 화면을
좌우로 절반씩 나눈다.

- 왼쪽 절반: P1이 P2를 바라보는 시점
- 오른쪽 절반: P2가 P1을 바라보는 시점
- 두 캐릭터 사이의 설정상 거리는 사람 키 약 3배인 약 5m다.
- 작은 부족 마을 공터의 같은 장소를 서로 반대 방향에서 본다.
- 각 절반의 중앙에는 상대 앞모습 캐릭터를 배치한다.
- 자기 뒷모습을 표시하는 경우 화면 하단 전경에 배치한다.
- 좌우 회피 위치는 각 절반 안의 두 고정 앵커로 구현하며 중앙 앵커는 만들지 않는다.

## 10. HUD

| 요소 | 표시 내용 |
|---|---|
| P1 `맞은 돌` | P1이 피격된 누적 횟수 |
| P2 `맞은 돌` | P2가 피격된 누적 횟수 |
| 남은 시간 | `matchSeconds`의 남은 시간 |
| 이벤트 피드백 | 명중, 회피, 유효하지 않은 손 상태, 최종 승패 |

체력바는 사용하지 않는다. 발사 이벤트 순간 양손 또는 무손이라 발사되지 않았을 때는 짧은
시각·음향 피드백을 줄 수 있지만 점수에는 영향을 주지 않는다.

## 11. 조정 가능한 값

| 필드명 | 권장 초기값 | 단위 | 의미 |
|---|---:|---|---|
| `fireIntervalSeconds` | 1.0 | 초 | 양쪽 플레이어의 반복 발사 이벤트 간격 |
| `matchSeconds` | 30 | 초 | 게임 총 제한시간 |
| `headSideThreshold` | 실측 필요 | 비율 | 캘리브레이션 중립선 대비 좌우 판정 기준 |
| `headSideHoldSeconds` | 0.1 | 초 | 좌우 상태 떨림을 막기 위한 최소 유지 시간 |
| `stoneTravelSeconds` | 0.25 | 초 | 돌 비행 연출 시간 |
| `throwAnimationSeconds` | 에셋별 조정 | 초 | 투척 프레임 전체 재생 시간 |
| `hitFaceDisplaySeconds` | 0.7 | 초 | 찡그린 얼굴 오버레이 유지 시간 |
| `calibrationSeconds` | 1.5 | 초 | 안정된 차렷 자세 기준 수집 시간 |
| `resultDisplaySeconds` | 2.0 | 초 | 결과 표시 후 다음 게임 전환 대기 |

`maxHealth`는 사용하지 않으며 설정에서도 제거한다.

## 12. 예외 / 엣지 케이스

- **양손 또는 무손**: 발사 이벤트는 소비되지만 돌과 투척 애니메이션은 생성하지 않는다.
- **트래킹 끊김**: 해당 플레이어의 입력과 발사 판정을 일시 중단하고 재연결/재캘리브레이션
  안내를 표시한다. 트래킹이 끊긴 사람에게 자동 명중을 부여하지 않는다.
- **동시 발사**: 양쪽 이벤트를 모두 판정한다. 서로 동시에 명중할 수 있다.
- **종료 시각과 발사 이벤트가 같은 프레임**: 제한시간 종료 판정을 우선하고 추가 발사를
  생성하지 않는다.
- **머리 중립 구간**: `Center`로 바꾸지 않고 마지막으로 확정된 `Left` 또는 `Right`를 유지한다.
- **연속 피격**: 피격 얼굴 표시 타이머만 갱신하며 명중 점수는 매번 정상적으로 증가한다.

## 13. 구현 완료 기준

- [ ] P1과 P2가 각자 카메라에서 얼굴과 양손을 모두 보인 차렷 자세로 캘리브레이션한다.
- [ ] 캘리브레이션 로딩 화면에 게임 로고, 본인 카메라, 자세 안내, 로딩 링, 본인/상대 상태,
      하단 순환 팁이 모두 표시된다.
- [ ] 상대방 ready 이벤트를 받으면 `준비 중` 배지가 `준비 완료` 배지로 바뀐다.
- [ ] 양쪽 캘리브레이션과 ready-check가 모두 끝나기 전에는 게임 타이머가 시작되지 않는다.
- [ ] 손 상태와 무관하게 양쪽 발사 이벤트가 일정한 시간 간격으로 계속 트리거된다.
- [ ] 이벤트 순간 오른손만 들면 오른쪽, 왼손만 들면 왼쪽으로 돌이 발사된다.
- [ ] 이벤트 순간 양손을 들었거나 두 손을 모두 내리면 돌이 발사되지 않는다.
- [ ] 투척 시 관절 회전 대신 손 방향에 맞는 캐릭터 애니메이션 프레임이 재생된다.
- [ ] 릴리즈 프레임과 돌 생성 시점이 일치한다.
- [ ] 캐릭터 위치는 항상 왼쪽 또는 오른쪽이며 가운데 상태가 없다.
- [ ] 고개 방향을 바꾸면 캐릭터가 대응하는 좌우 위치로 이동한다.
- [ ] 돌 목표 방향과 상대 위치가 같으면 명중, 다르면 회피로 처리된다.
- [ ] 피격 시 `grimacing.png`가 기존 얼굴 위를 덮고 일정 시간 후 사라진다.
- [ ] 체력과 체력바가 존재하지 않으며 제한시간 전에 피격 수로 게임이 종료되지 않는다.
- [ ] 제한시간 종료 시 더 많이 명중시킨 플레이어가 승리하고 같으면 무승부다.
- [ ] HUD의 피격 횟수와 남은 시간이 판정 결과와 일치한다.

## 14. 구현 작업 메모

- 기존 `StoneThrowGame.cs`의 손 유지형 발사 타이머를 고정 주기 이벤트 방식으로 변경한다.
- 양손 우선순위와 체력/즉사 로직을 제거한다.
- 캐릭터 프레임 애니메이션 재생 컴포넌트와 릴리즈 이벤트를 연결한다.
- `CavemanSilhouette`의 실시간 관절 투척 표현은 이 게임의 발사 동작에는 사용하지 않는다.
- 좌/우 위치 앵커와 `HeadSide` 이진 상태를 추가한다.
- `StoneThrowHud`에서 체력바를 제거한다.
- 캘리브레이션 완료 이벤트를 양쪽 ready-check에 연결한다.
