# 1. 돌던지기 (Stone Throw)

> 코드: `Assets/Scripts/Minigames/StoneThrow/StoneThrowGame.cs`, `StoneThrowHud.cs`.
> 씬: `Assets/Scenes/StoneThrow.unity`.

## 0. 한 줄 요약

손을 든 채로 있으면 자동으로 돌이 계속 날아간다 — 어느 손을 드느냐로 조준을, 머리를
어느 쪽으로 기울이느냐로 회피를 계속 바꿔가는 실시간 공방.

## 1. 플레이어가 하는 일

| 동작 | 결과 |
|---|---|
| 오른손 들기 | 그 손이 들린 채로 발사 타이밍이 될 때, 상대의 **오른쪽**을 조준 |
| 왼손 들기 | 상대의 **왼쪽**을 조준 |
| 양손 다 들기 | 오른손 우선(오른쪽 조준으로 처리) |
| 손을 완전히 내림 | 발사 대기 진행이 취소됨 — 다시 들면 처음부터 다시 기다려야 함(중간부터 이어지지 않음) |
| (상대 공격을 받는 쪽) 머리를 좌/우로 기울임 | 그 순간 자신을 조준한 방향과 기울인 방향이 같으면 회피 |
| (상대 공격을 받는 쪽) 머리를 안 기울이거나 살짝만 기울임 | 명중 처리 |

## 2. 입력 신호 (PoseInputHub API)

| 신호 | 메서드/필드 | 이 게임에서의 의미 |
|---|---|---|
| 오른손 들림 | `state.IsHandRaised(rightHand: true)` | 참이면 오른쪽 조준 후보 |
| 왼손 들림 | `state.IsHandRaised(rightHand: false)` | 참이면 왼쪽 조준 후보 |
| 머리 기울기 | `state.HeadTiltRatio()` | 양수=오른쪽, 음수=왼쪽으로 기운 정도(몸통 길이 대비 비율) |
| 트래킹 여부 | `state.IsTracked` | false면 그 사람은 이번 판정에서 열외 (아래 "예외" 참고) |

`PlayerPoseState`는 `PoseInputHub.Instance.Get(PlayerId.P1 / P2)`로 얻는다. 이 게임은 위
4개 외에 다른 신호(입 벌림, 점프 높이 등)를 쓰지 않는다.

## 3. 규칙 / 상태 흐름

이 게임은 명시적 상태 머신 없이, 플레이어별로 독립된 "발사 타이머"만 돌아간다(P1용 하나,
P2용 하나 — 서로 완전히 독립적으로, 동시에 진행됨).

```
[대기] --손이 하나라도 들림--> [충전 중] --fireIntervalSeconds 경과--> 발사 판정 실행 후 [대기]로
[충전 중] --양손 다 내림--> [대기] (충전 진행 취소, 처음부터 다시)
```

**발사 판정 실행 시점에 하는 일** (그 프레임에서 즉시, 순서대로):

1. 그 순간 오른손이 들려 있으면 조준 방향 = 오른쪽, 아니면(왼손만 들려 있으면) 왼쪽.
   (충전 시작 시점이 아니라 **발사되는 순간**의 손 상태를 본다 — 충전 중에 손을 바꿔도
   반영됨.)
2. 상대가 트래킹되고 있으면: 상대의 `HeadTiltRatio()`를 읽어
   - `dodgeTiltThreshold`보다 크면 → 회피 방향 = 오른쪽
   - `-dodgeTiltThreshold`보다 작으면 → 회피 방향 = 왼쪽
   - 그 사이(거의 안 기울임)면 → 회피 방향 없음
3. 상대가 트래킹 안 되고 있으면 → 무조건 명중 처리(회피 불가능한 것으로 간주).
4. 조준 방향과 회피 방향이 **같으면** 회피, **다르면(또는 회피 방향이 없으면)** 명중.
5. 명중이면 맞은 사람의 누적 피격 수를 올리고 HUD/표정 갱신, 회피면 텍스트만 표시.
6. 던진 사람 쪽에서 맞은 사람 쪽으로 돌 하나가 시각적으로 날아간다(연출, 판정에는 영향 없음).
7. 타이머를 0으로 되돌리고 같은 사람에 대해 다시 1번부터.

P1의 타이머/판정과 P2의 타이머/판정은 서로 완전히 독립이다 — 두 사람이 동시에 서로를
맞힐 수 있다.

## 4. 승리 / 패배 조건

`matchSeconds`(기본 30초) 경과 시점에 각자의 누적 피격 수를 비교해 **더 적게 맞은 쪽이
승리**한다. 정확히 같으면 무승부. (즉 "많이 맞힌 사람"이 아니라 "적게 맞은 사람"이 이기는
스탯을 본다 — 구현상 자신의 피격 수가 곧 상대의 명중 수이므로 결과는 동일하다.)

## 5. 화면 구도

- 카메라: `orthographicSize = 3`. 배경 스프라이트가 못 불러와졌을 때만 보이는 폴백 단색
  배경(`0.79, 0.69, 0.53`, 살구빛 베이지)을 깔아둔다.
- 배경: 카메라 뷰를 항상 꽉 채우도록 종횡비에 맞게 스케일된 cover 방식 배경 한 장.
- 캐릭터: 화면 왼쪽에 P1, 오른쪽에 P2 — 좌우 대칭 위치(중앙에서 좌우로 각각 같은 거리).
  이 게임 전용 특수 자세는 없고, 공용 캐릭터 리깅이 손 든 상태를 그대로 반영한다.
- 투사체(돌)는 던진 사람 캐릭터 위치 근처에서 생성돼 맞은 사람 위치까지 날아간 뒤 사라진다
  (회피 시에는 목표를 살짝 지나쳐서 빗나간 느낌을 준다).

## 7. 연출 / 피드백

- **돌 궤적**: 짧은 시간 동안 던진 위치→맞은 위치로 직선 이동 + 빙글빙글 회전. 회피면
  목표를 살짝 지나쳐서 착지.
- **피격 표정**: 맞은 사람의 표정이 짧게(1초 미만) 바뀐다 — 누적 피격 수가 적을 땐 가벼운
  찡그림, 중간 이상이면 이빨이 하나씩 빠진 표정으로 단계적으로 험해진다. 잠시 후 원래
  표정으로 복귀.
- **텍스트 피드백**: 명중/회피 시 즉시, 라운드 종료 시 승패 문구가 더 길게 표시된 뒤 다음
  라운드로 넘어간다.
- **사운드**: 미구현. TODO.

## 8. 조정 가능한 값

| 필드명 | 기본값 | 단위 | 의미 |
|---|---|---|---|

## 10. 예외 / 엣지 케이스

- **한쪽이 트래킹 안 됨(`IsTracked == false`)**: 그 사람은 손을 들어도 발사 타이머가 진행되지
  않는다(공격 불가). 반대로 그 사람이 "회피 대상"일 때는 회피 불가능한 것으로 보고 무조건
  명중 처리한다 — 즉 트래킹이 끊기면 공격은 못 하지만 방어도 못 한다.
- **양쪽이 정확히 같은 프레임에 서로를 명중**: 문제 없음 — 두 타이머가 독립적이라 각자
  판정되고 누적치에 정상 반영된다.
- **동점으로 시간 종료**: 무승부 처리(승자 없음으로 `MatchController`에 보고).
- **손을 든 채로 라운드가 끝남**: 다음 라운드로 넘어가므로 별도 정리 로직 불필요(씬 전환 시
  이 게임의 타이머 상태는 자동으로 사라짐).

## 11. 공용 의존성

- `PoseInputHub` / `PoseStreamReceiver` — 입력팀 담당, [GETTING_STARTED.md](../../GETTING_STARTED.md) 참고
- `CavemanSilhouette` (+ `Assets/Prefabs/Caveman_P1.prefab`, `Caveman_P2.prefab`) — 캐릭터 리깅, 표정 교체(`SetFace`/`ResetFace`) API 포함
- `MatchController` — 라운드 진행/최종 점수 집계. 승자가 정해지는 순간
  `ReportRoundResult(winner)` 한 번, 이어서 `LoadNextRound()` 한 번만 호출하면 됨(`winner`는
  `PlayerId?` — 무승부면 `null`)
- `ArtAssets` — 프롭/캐릭터/게임별 스프라이트 로더(`LoadProp`, `LoadCharacter`, `LoadStoneThrow` 등), 배경 cover 배치(`CreateBackground`), 스프라이트 폭 맞추기(`FitWidth`)
- `HudWidgets` — HUD Canvas를 카메라 프레임에 맞추는 `ConfigureForGameCamera`, 이미지/텍스트 위젯 생성(`CreateImage`, `CreateText`)
