# 빌드 가이드 (macOS / Windows)

이 문서는 **배포용 실행파일(macOS dmg / Windows 폴더)을 만드는 방법**을 다룬다. 소스에서
바로 실행해서 LAN 플레이테스트하는 방법은
[멀티플레이_실행_명령어.md](멀티플레이_실행_명령어.md)를 참고 — 그쪽은 팀원 PC마다 Python과
Unity Editor를 켜놓고 진행하는 개발용 절차고, 이 문서는 "완성된 실행파일 하나를 다른 사람
컴퓨터에 전달"하는 배포용 절차다. 전체 설계 배경은
[배포_아키텍처_설계.md](배포_아키텍처_설계.md) 참고.

## 0. 구조 요약

빌드 결과물(`.app`/`.exe`)은 Unity 게임 자체와, 카메라/마이크로 포즈를 인식하는 Python
서브프로세스(`vision-server`)가 실행파일 안에 함께 들어있는 형태다. 사용자는 이 실행파일
하나만 받으면 되고, Python을 따로 설치하거나 `vision-server`를 손으로 켤 필요가 없다 —
`VisionServerLauncher.cs`가 Hub 화면에서 호스트로 시작/접속/1인 플레이를 선택하는 순간 알아서
켜고, 게임을 끄면 같이 끈다.

**PyInstaller(Python → 실행파일 패키징 도구)는 크로스 컴파일이 안 된다.** macOS에서 만든
`vision-server`는 macOS에서만, Windows에서 만든 건 Windows에서만 돈다. 그래서 각 OS용
배포판은 **그 OS에서 직접** 만들어야 한다 — 아래 macOS/Windows 절차가 따로 있는 이유다.

| | macOS | Windows |
|---|---|---|
| 상태 | 실제로 dmg까지 만들어서 실행 확인 완료 | 구조만 준비됨, 팀원 머신에서 실측 필요 |
| vision-server 패키징 | 터미널 명령 직접 실행 | `build_windows.bat` 더블클릭 |
| Unity 빌드 | Unity Editor 메뉴 | Unity Editor 메뉴(동일) |
| 최종 결과물 | `UgaUgaGame.dmg` | `Build\Windows\` 폴더(zip으로 압축해서 전달) |

## 1. macOS 빌드

### 1.1 사전 준비

- Unity Hub에 Unity **6000.5.5f1** 설치, `pc-game/`을 그 버전으로 열어둘 것.
- Python 3.9 이상 (`python3 --version`으로 확인. 없으면 `brew install python3` 또는
  [python.org](https://www.python.org/downloads/macos/)에서 설치).
- 이 레포를 통째로 클론해둘 것 — `vision-server/models/pose_landmarker_lite.task`가 이미
  git에 커밋되어 있으므로 별도로 받을 필요 없다.

### 1.2 vision-server 패키징

터미널에서:

```bash
cd vision-server
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
pip install pyinstaller

# face_landmarker.task가 없다면(README.md 참고) 먼저 받는다
ls models/face_landmarker.task || curl -L -o models/face_landmarker.task \
  "https://storage.googleapis.com/mediapipe-models/face_landmarker/face_landmarker/float16/latest/face_landmarker.task"

pyinstaller vision-server.spec --noconfirm --clean
```

`vision-server/dist/vision-server/vision-server`가 생기면 성공. 카메라 없이 빠르게
검증하려면:

```bash
./dist/vision-server/vision-server --check-models
./dist/vision-server/vision-server --list-audio-devices
```

첫 실행은 matplotlib 폰트 캐시 초기화 때문에 ~10초 정도 걸린다(정상 — mediapipe가 내부적으로
matplotlib을 끌어들이는 진짜 의존성이라 뺄 수 없다, 실측 확인됨). 이후 Unity가 자동으로 켤
때도 매번 이 정도 지연이 있다는 뜻이니 참고.

### 1.3 Unity 빌드 + dmg 생성

Unity Editor에서 `pc-game` 프로젝트를 연 상태로 메뉴:

```
Tools > UGAUGA > Build Dev Player + DMG (macOS)
```

이 한 메뉴가 순서대로 다음을 전부 처리한다:

1. Standalone 빌드 (`Build/macOS/pc-game.app`)
2. 방금 만든 `vision-server/dist/vision-server/`를
   `pc-game.app/Contents/Resources/vision-server/`에 자동 복사
3. vision-server를 끼워넣으면서 깨지는 Unity의 ad-hoc 서명을 `codesign --force --deep
   --sign -`로 재서명 (이 단계를 건너뛰면 배포 후 "손상되어 열 수 없음" 에러가 남 — 3장
   참고)
4. `hdiutil`로 `Build/macOS/UgaUgaGame.dmg` 생성

Unity 콘솔에 `[DevBuildTools] dmg 생성 완료: .../UgaUgaGame.dmg`가 뜨면 끝. vision-server만
따로 다시 만들었다면(1.2를 재실행했다면) 이 메뉴도 다시 실행해야 새 버전이 반영된다.

Unity 빌드만 필요하고 dmg는 필요 없다면 `Build Dev Player (macOS)`만 실행해도 된다 — 다만
그 경우 2~3단계(vision-server 동봉 + 재서명)까지는 여전히 자동으로 같이 처리된다.

### 1.4 확인

```bash
open Build/macOS/UgaUgaGame.dmg
```

마운트된 볼륨에서 `pc-game.app`을 실행해 Hub 화면이 뜨는지 확인한다. 로컬에서 직접 만든
dmg는 quarantine(격리) 표시가 없어서 바로 열리지만, **Slack/카카오톡/구글드라이브 등으로
전달받은 dmg는 첫 실행 시 macOS가 "확인되지 않은 개발자" 경고를 띄운다** — 정상이다(3장
참고), Finder에서 앱을 control-클릭(또는 우클릭) → "열기"를 선택하면 그다음부터는 경고 없이
실행된다.

## 2. Windows 빌드

> 아직 실제 Windows 머신에서 검증되지 않았다 — 아래는 준비된 구조이며, 처음 시도할 때 막히는
> 부분이 있으면 이 문서를 업데이트해야 한다.

### 2.1 사전 준비

- Unity Hub에 Unity **6000.5.5f1** 설치, `pc-game/`을 그 버전으로 열어둘 것.
- Python 3.9 이상, 설치 화면에서 **"Add python.exe to PATH" 체크 필수**
  ([python.org](https://www.python.org/downloads/windows/)).
- 이 레포를 통째로 클론해둘 것.

### 2.2 vision-server 패키징

`vision-server` 폴더 안의 `build_windows.bat`을 더블클릭한다. 다음을 자동으로 처리한다:

1. `.venv` 가상환경 생성 (없으면)
2. `requirements.txt` + `pyinstaller` 설치
3. `models/face_landmarker.task`가 없으면 자동 다운로드
4. `pyinstaller vision-server.spec --noconfirm --clean` 실행

`dist\vision-server\vision-server.exe`가 생기면 성공 콘솔 메시지가 뜬다. 검증:

```powershell
dist\vision-server\vision-server.exe --check-models
dist\vision-server\vision-server.exe --list-audio-devices
```

### 2.3 Unity 빌드

Unity Editor에서 메뉴:

```
Tools > UGAUGA > Build Dev Player (Windows)
```

`Build\Windows\pc-game.exe`를 만들고, 방금 만든 `vision-server\dist\vision-server\`를
`pc-game.exe`와 같은 폴더 밑 `vision-server\`에 자동 복사한다. (macOS의 dmg 자동 생성 메뉴에
해당하는 Windows용 인스톨러 자동화는 아직 없음 — 2.4 참고.)

### 2.4 배포

`Build\Windows\` 폴더 전체를 압축(zip)해서 전달한다. 받는 사람은 압축을 풀고 `pc-game.exe`를
바로 실행하면 된다 — Windows Defender SmartScreen이 "알 수 없는 게시자" 경고를 띄우면 "추가
정보" → "실행"으로 우회한다(정상, 3장 참고).

## 3. 공통 참고사항

- **서명/인증서**: macOS든 Windows든 유료 개발자 서명은 하지 않는다(몰입캠프 데모 규모 판단).
  받는 사람이 처음 실행할 때 OS가 경고를 한 번 띄우는 건 정상이고, 우회 방법은 위에 적힌
  대로다. "손상됨"/"실행할 수 없음" 같은 더 심한 에러가 뜨면 버그이니 이 문서나
  [배포_아키텍처_설계.md](배포_아키텍처_설계.md) 3장을 확인한다.
- **카메라/마이크 권한**: 실행파일을 처음 켜면 OS가 카메라·마이크 접근 허용 팝업을 띄운다.
  이때 반드시 "허용"을 눌러야 포즈 인식이 동작한다 — 게임 UI에 아직 이 안내 문구가 없으니
  플레이어에게 미리 말해줄 것.
- **vision-server를 못 찾는다는 로그**: Unity 콘솔에 `[DevBuildTools] vision-server
  PyInstaller 산출물을 못 찾아 동봉을 건너뜁니다`가 뜨면, vision-server 패키징(1.2/2.2)을
  먼저 하지 않고 Unity 빌드부터 돌린 것이다 — 순서를 지켜서 다시 빌드한다.
- **방화벽 포트**: 온라인 2인 플레이 시 호스트 PC에서 UDP 9100/9101, TCP 9200 인바운드를
  허용해야 할 수 있다 — [멀티플레이_실행_명령어.md](멀티플레이_실행_명령어.md) 7장 참고.
- **다시 빌드해야 하는 경우**: Unity 코드/씬만 바뀌었다면 1.3/2.3만 다시 실행하면 된다(방금
  만든 vision-server를 그대로 재사용). `vision-server/main.py`나 `models/`가 바뀌었다면
  1.2/2.2부터 다시 해야 한다.
