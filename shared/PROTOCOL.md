# 통신 프로토콜 스펙 (v0.1 — Day 1 기준)

폰 ↔ PC 간 UDP 통신 포맷. Tier 1(임계값 분류)을 우선 구현하는 8일 일정에 맞춰
Day 1엔 **JSON 텍스트 포맷**으로 시작한다. 페이로드 최적화(바이너리 패킹)는
Day 6 레이턴시 튜닝 스프린트에서 필요하면 진행한다 (기획서 3-2, 5 참고).

같은 로컬 네트워크(가능하면 폰 핫스팟에 PC 직결)에서 동작한다고 가정.

## 포트

| 용도 | 포트 | 방향 |
|---|---|---|
| 시간 동기화 (ping/pong) | UDP 9001 | PC → 폰 (ping), 폰 → PC (pong) |
| 센서 스트리밍 (가속도/자이로) | UDP 9000 | 폰 → PC |
| 웹캠 비전 결과 (MediaPipe → Unity) | UDP 9002 | vision-server(Python) → PC(Unity) |

포트는 로컬 상수로 두고 필요하면 나중에 설정 파일로 뺀다.

## 1. 시간 동기화 (NTP 핑퐁)

기획서 3-1의 알고리즘을 그대로 구현한다. **PC가 클라이언트, 폰이 서버** 역할
(PC 기준 시각으로 모든 걸 정렬해야 하므로).

### PING (PC → 폰, port 9001)
```json
{"type": "ping", "seq": 3, "t1": 1721234567890.123}
```
- `t1`: PC가 송신하는 순간의 PC 시각 (ms, `double`)

### PONG (폰 → PC, port 9001, ping 수신 즉시 응답)
```json
{"type": "pong", "seq": 3, "t1": 1721234567890.123, "t2": 1721234567895.500, "t3": 1721234567895.600}
```
- `t1`: 받은 ping의 t1을 그대로 echo
- `t2`: 폰이 ping을 수신한 순간의 폰 시각
- `t3`: 폰이 pong을 송신하는 순간의 폰 시각 (t2와 t3 사이 처리 시간은 최소화)

### PC 측 계산 (pong 수신 시각 t4 기준)
```
RTT          = (t4 - t1) - (t3 - t2)
Clock Offset = ((t2 - t1) + (t3 - t4)) / 2      # phone_clock = pc_clock + offset
```
- 연결 시 20회 반복 → offset은 **중앙값(median)** 사용 (평균은 아웃라이어에 취약)
- 이후 센서 패킷의 폰 타임스탬프를 PC 기준으로 바꿀 때: `pc_time = phone_time - offset`
- 재연결/네트워크 변화 감지 시 재동기화 (예: 30초마다 5회 정도 재측정해 offset 드리프트 보정)

## 2. 센서 스트리밍 (폰 → PC, port 9000)

60~100Hz로 전송. 페이로드는 최소한으로 (기획서 3-2).

```json
{"seq": 10432, "t": 1721234567900.250, "ax": 0.12, "ay": 9.81, "az": -0.05, "gx": 0.0, "gy": 1.23, "gz": -0.4}
```

| 필드 | 의미 |
|---|---|
| `seq` | 증가하는 패킷 시퀀스 번호 (손실 감지용) |
| `t` | 샘플링 시점의 **폰** 시각 (ms) — PC에서 offset으로 보정해서 사용 |
| `ax, ay, az` | 가속도계 3축 (m/s²) |
| `gx, gy, gz` | 자이로 3축 각속도 (deg/s 또는 rad/s — 팀에서 단위 통일, 아래 "결정 필요" 참고) |

PC 수신 측은 `seq` 역전/누락으로 패킷 손실·순서 뒤바뀜을 감지하고 오래된 패킷은 버린다.

## 3. 웹캠 비전 결과 (Python vision-server → PC Unity, port 9002)

Day 2 작업 범위. 우선 필요한 두 가지 판정만 전송.

```json
{"t": 1721234567900.250, "guard_up": true, "crouch": false, "pose_confidence": 0.91}
```

- `t`: 프레임 캡처 시각 (PC 로컬 시각 기준 — vision-server는 PC에서 돌아가므로 offset 보정 불필요)
- `guard_up`: 방패 패링 자세 판별 결과
- `crouch`: 쭈그리기(회피) 판별 결과
- `pose_confidence`: MediaPipe landmark visibility 기반 신뢰도 (0~1)

## 결정 필요 (팀 회의에서 확정할 것)

- [ ] 자이로 단위: deg/s vs rad/s (Unity `Gyroscope.rotationRate`는 rad/s 기준 — 통일 필요)
- [ ] 센서 전송 주기: 60Hz vs 100Hz (폰 발열/배터리와 트레이드오프, 기획서 7 리스크 참고)
- [ ] 판정 윈도우 값 (웹캠 기반 ±250~300ms은 기획서 추천값, 실측 후 조정)
